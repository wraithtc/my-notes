背景：
1. 用户拍摄宠物食品包装袋的配料表照片 → OCR 识别配料文字 → 逐项分析每个配料对猫/犬的好处和坏处
2. 不做具体品牌/产品的检索，不查条形码，纯基于配料表做成分分析

## 二、系统架构方案

### 核心流程（极简）

```
用户拍照 → OCR 识别配料表 → 配料解析与标准化 → 知识库匹配 → 生成分析报告
```

### 详细流程

```
┌───────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────┐
│ 用户拍照    │     │  OCR 识别     │     │  配料解析与    │     │  分析与报告    │     │          │
│ 配料表     │────▶│  配料表文字   │────▶│  标准化       │────▶│  生成        │────▶│ 展示结果  │
│           │     │              │     │              │     │              │     │          │
└───────────┘     └──────────────┘     └──────┬───────┘     └──────┬───────┘     └──────────┘
                                              │                    │
                                       ┌──────▼───────┐     ┌─────▼──────┐
                                       │  自建配料知识库│     │ LLM + 规则  │
                                       │  (PostgreSQL) │     │ 引擎       │
                                       └──────────────┘     └────────────┘
```

### 三大核心模块

#### 模块 1：OCR 配料表识别

```
输入：用户拍摄的宠物食品包装袋配料表照片
处理：
  - 图片预处理（矫正、增强对比度）
  - OCR 文字识别（中英文混合）
  - 输出配料表原始文本
技术选型：
  - 方案 A：调用云端 OCR API（百度/腾讯/阿里 OCR，中文识别好）
  - 方案 B：开源 PaddleOCR（可私有化部署，免费）
  - 方案 C：直接用多模态 LLM（GPT-4o / Claude）识别图片中的文字
推荐：MVP 用方案 C（多模态 LLM 直接读图），后期可切换方案 B 降本
```

#### 模块 2：配料解析与标准化

```
输入：OCR 识别出的配料表原始文本
  例："配料：新鲜鸡肉(30%)、糙米(20%)、鸡脂(保存混合生育酚)、
       干燥甜菜粕、磷酸氢钙、氯化钾、维生素A补充剂、维生素B12补充剂、
       硫酸锌、硫酸亚铁、BHA、迷迭香提取物"

处理：
  Step 1 — 文本清洗
    - 去除"配料："、"Ingredients:" 等前缀
    - 统一分隔符（中英文逗号、顿号 → 统一分隔）

  Step 2 — 拆分为单个配料项
    → ["新鲜鸡肉(30%)", "糙米(20%)", "鸡脂(保存混合生育酚)", ...]

  Step 3 — 标准化匹配
    "新鲜鸡肉(30%)"        → 鸡肉 (id=1)
    "鸡脂(保存混合生育酚)"   → 鸡脂 (id=34)
    "维生素A补充剂"         → 维生素A (id=102)
    "BHA"                  → BHA (id=89, risk_level=caution)

  Step 4 — 配料分类
    · 动物蛋白 → 鸡肉
    · 谷类碳水 → 糙米
    · 动物脂肪 → 鸡脂
    · 防腐剂   → BHA（⚠️ 标记争议）
```

#### 模块 3：分析报告生成

```
输入：标准化后的配料列表 + 知识库数据
输出：

  📊 整体评级：B+
  🐱 适用宠物：成年猫 | 幼猫 | 全阶段猫

  ✅ 优势配料：
    · 鸡肉（30%）：优质动物蛋白，猫咪必需氨基酸来源
    · 糙米（20%）：易消化的碳水来源，提供持久能量
    · 迷迭香提取物：天然抗氧化剂，安全性好

  ⚠️ 需关注：
    · BHA：合成防腐剂，潜在健康争议，建议选择使用天然抗氧化剂的产品

  📋 逐项分析：
    [每个配料的详细说明...]

  💡 建议：
    · 蛋白质来源单一（仅鸡肉），可轮换不同蛋白源的猫粮
    · 含谷物，如有谷物过敏的猫咪需注意
```

## 三、宠物食品配料知识库的构建

> 配料知识库是整个系统的数据基石。公开 API 只能告诉你"产品里有什么配料"，但无法告诉你"这个配料对猫/犬好不好"。这一层必须自建。

### 3.1 知识库的两种形态

```
形态 A：结构化数据库（规则引擎用）
  → 每个配料一条记录，字段固定，支持精确查询
  → 用于：毒性标记、过敏原判断、评级计算

形态 B：向量知识库（LLM/RAG 用）
  → 每个配料一段专业描述文本，生成 Embedding
  → 用于：自然语言问答、个性化建议生成

推荐：两者同时建设，共用同一份数据源
```

---

### 3.2 配料数据模型设计

#### 核心表：ingredients（配料主表）

```sql
CREATE TABLE `ingredients` (
    `id`              INT AUTO_INCREMENT PRIMARY KEY,
    `name_zh`         VARCHAR(200) NOT NULL COMMENT '中文名：鸡肉',
    `name_en`         VARCHAR(200) COMMENT '英文名：Chicken',
    `aliases`         JSON COMMENT '别名列表：["鸡胸肉","chicken breast","去骨鸡肉"]',
    `category`        VARCHAR(50) NOT NULL COMMENT '分类（见下方枚举）',
    `sub_category`    VARCHAR(50) COMMENT '子分类',
    `description`     TEXT COMMENT '通用描述',

    -- 风险评估
    `risk_level`      VARCHAR(20) DEFAULT 'safe' COMMENT 'safe / caution / dangerous / toxic',
    `risk_reason`     TEXT COMMENT '风险原因说明',

    -- 对猫的影响
    `cat_benefit`     TEXT COMMENT '对猫的好处',
    `cat_risk`        TEXT COMMENT '对猫的风险',
    `cat_allergen`    TINYINT(1) DEFAULT 0 COMMENT '是否猫常见过敏原',
    `cat_relevance`   VARCHAR(20) DEFAULT 'medium' COMMENT 'high/medium/low',

    -- 对犬的影响
    `dog_benefit`     TEXT COMMENT '对犬的好处',
    `dog_risk`        TEXT COMMENT '对犬的风险',
    `dog_allergen`    TINYINT(1) DEFAULT 0 COMMENT '是否犬常见过敏原',
    `dog_relevance`   VARCHAR(20) DEFAULT 'medium' COMMENT 'high/medium/low',

    -- 营养标签
    `key_nutrients`   JSON COMMENT '主要营养成分 ["蛋白质","维生素B12","锌"]',
    `nutrient_density` VARCHAR(20) COMMENT 'high/medium/low',

    -- 元数据
    `source`          VARCHAR(100) COMMENT '数据来源标注',
    `updated_at`      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `verified`        TINYINT(1) DEFAULT 0 COMMENT '是否经专业审核',

    UNIQUE KEY `uk_name_zh` (`name_zh`),
    INDEX `idx_category` (`category`),
    INDEX `idx_risk_level` (`risk_level`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 分类枚举（category 字段）

```
protein_animal      -- 动物蛋白（鸡肉、牛肉、鱼肉、鸡蛋...）
protein_plant       -- 植物蛋白（大豆、豌豆蛋白...）
carb_grain          -- 谷类碳水（糙米、玉米、小麦...）
carb_grain_free     -- 无谷碳水（土豆、红薯、豌豆...）
fat_animal          -- 动物脂肪（鸡脂、牛油...）
fat_plant           -- 植物脂肪（亚麻籽油、椰子油...）
fiber               -- 纤维（甜菜粕、南瓜、车前子壳...）
vitamin             -- 维生素类添加剂
mineral             -- 矿物质类添加剂
preservative        -- 防腐剂（BHA、混合生育酚...）
antioxidant         -- 抗氧化剂
colorant            -- 着色剂
flavor_enhancer     -- 风味增强剂
bind_thickener      -- 粘合剂/增稠剂（卡拉胶、瓜尔胶...）
supplement          -- 功能性补充剂（葡萄糖胺、益生菌...）
other               -- 其他
```

#### 辅助表：ingredient_nutrients（配料营养成分关联表）

```sql
CREATE TABLE `ingredient_nutrients` (
    `id`               INT AUTO_INCREMENT PRIMARY KEY,
    `ingredient_id`    INT NOT NULL,
    `nutrient_name`    VARCHAR(100) COMMENT '营养素名称：粗蛋白质',
    `nutrient_name_en` VARCHAR(100) COMMENT 'Protein',
    `amount_per_100g`  DECIMAL(10,2) COMMENT '每100g含量',
    `unit`             VARCHAR(20) COMMENT 'g / mg / μg / IU',
    `data_source`      VARCHAR(100) COMMENT 'USDA FDC / 自测 / 文献',
    UNIQUE KEY `uk_ingredient_nutrient` (`ingredient_id`, `nutrient_name`),
    FOREIGN KEY (`ingredient_id`) REFERENCES `ingredients`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 辅助表：ingredient_standards（配料合规标准）

```sql
CREATE TABLE `ingredient_standards` (
    `id`              INT AUTO_INCREMENT PRIMARY KEY,
    `ingredient_id`   INT NOT NULL,
    `standard_body`   VARCHAR(50) COMMENT 'AAFCO / FEDIAF / GB(国标)',
    `allowed_cat`     TINYINT(1) COMMENT '猫粮中是否允许使用',
    `allowed_dog`     TINYINT(1) COMMENT '犬粮中是否允许使用',
    `max_percentage`  DECIMAL(5,2) COMMENT '最大允许占比（%）',
    `notes`           TEXT,
    FOREIGN KEY (`ingredient_id`) REFERENCES `ingredients`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

```
你是一名宠物营养学专家。请为以下宠物食品配料生成详细分析：

  "category": "分类",
  "cat_benefit": "对猫的好处...",
  "cat_risk": "对猫的风险...",
```

### 3.4 配料标准化（关键难题）

用户输入和食品包装上的配料名称千奇百怪，必须标准化后才能匹配知识库：

```
标准化流程：

输入文本 → 清洗 → 分词 → 同义词匹配 → 知识库 ID

示例：
  "新鲜去骨鸡胸肉（含鸡肉精华）" 
    → 清洗：去除括号内容 → "新鲜去骨鸡胸肉"
    → 分词提取核心：["鸡肉", "鸡胸肉"]
    → 同义词匹配：aliases 包含 "鸡胸肉"
    → 命中 ingredients.id = 1 (鸡肉)

实现方式：
  - 方案 A：基于 Elasticsearch 的模糊匹配 + 同义词词典
  - 方案 B：基于 LLM 的意图理解（准确但慢、贵）
  - 方案 C：正向最大匹配 + 编辑距离（轻量、够用）
  - 推荐先用方案 C 启动，后期叠加方案 A
```

#### 别名表设计

```sql
CREATE TABLE `ingredient_aliases` (
    `id`             INT AUTO_INCREMENT PRIMARY KEY,
    `ingredient_id`  INT NOT NULL,
    `alias`          VARCHAR(200) NOT NULL COMMENT '鸡胸肉',
    `language`       VARCHAR(10) DEFAULT 'zh' COMMENT 'zh / en',
    `source`         VARCHAR(50) COMMENT 'manual / opff / user',
    UNIQUE KEY `uk_alias_lang` (`alias`, `language`),
    INDEX `idx_alias` (`alias`),
    FOREIGN KEY (`ingredient_id`) REFERENCES `ingredients`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

```
       └───────────────┘
```

### 3.6 MVP 阶段的知识库规模建议

```
Phase 1（MVP，覆盖 90% 场景）：

  核心配料    150-200 个
  ├─ 动物蛋白       30 个  （鸡肉、牛肉、三文鱼、金枪鱼、羊肉、火鸡、鸭肉、鹿肉、
  │                         鸡肉粉、鱼肉粉、鸡蛋、肉骨粉...）
  ├─ 碳水来源       25 个  （糙米、玉米、小麦、土豆、红薯、豌豆、燕麦、大麦、
  │                         木薯、鹰嘴豆...）
  ├─ 脂肪来源       15 个  （鸡脂、鱼油、亚麻籽油、椰子油、牛油、葵花籽油...）
  ├─ 纤维来源       10 个  （甜菜粕、南瓜、车前子壳、菊苣根、豌豆纤维...）
  ├─ 添加剂         50 个  （防腐剂、抗氧化剂、着色剂、增稠剂、调味剂...）
  ├─ 维生素/矿物质   40 个  （维生素A-K、钙磷锌铁铜锰硒...）
```

#### 配料解析 + 匹配核心逻辑

```python
import re
import aiomysql

def parse_ingredients(text: str) -> list[str]:
    """将配料表原文拆分为单个配料项"""
    # 去除"配料：" / "Ingredients:" 前缀
    text = re.sub(r'^(配料[表:]?|Ingredients?:)\s*', '', text.strip())
    # 统一分隔符
    text = text.replace('，', ',').replace('、', ',').replace('；', ',')
    # 拆分
    items = [item.strip() for item in text.split(',') if item.strip()]
    return items


def clean_item(item: str) -> str:
    """清洗单个配料项，提取核心名称"""
    # 去除百分比 "鸡肉(30%)" → "鸡肉"
    item = re.sub(r'[（(]\s*\d+\.?\d*\s*%\s*[）)]', '', item)
    # 去除括号内的修饰 "(保存混合生育酚)" → ""
    item = re.sub(r'[（(].*?[）)]', '', item)
    # 去除常见前缀
    for prefix in ['新鲜', '脱水', '干燥', '冷冻', '优质', '天然']:
        item = item.replace(prefix, '')
    return item.strip()


async def match_ingredient(item: str, pool) -> dict | None:
    """配料项 → 匹配知识库（MySQL）"""
    cleaned = clean_item(item)

    async with pool.acquire() as conn:
        async with conn.cursor(aiomysql.DictCursor) as cur:

            # 1. 精确匹配 name_zh
            await cur.execute(
                "SELECT * FROM ingredients WHERE name_zh = %s", (cleaned,)
            )
            result = await cur.fetchone()
            if result:
                return dict(result)

            # 2. 别名匹配
            await cur.execute("""
                SELECT i.* FROM ingredients i
                JOIN ingredient_aliases a ON a.ingredient_id = i.id
                WHERE a.alias = %s
            """, (cleaned,))
            result = await cur.fetchone()
            if result:
                return dict(result)

            # 3. 模糊匹配（包含关系，MySQL 用 CONCAT）
            await cur.execute("""
                SELECT * FROM ingredients
                WHERE %s LIKE CONCAT('%%', name_zh, '%%')
                   OR name_zh LIKE CONCAT('%%', %s, '%%')
                LIMIT 1
            """, (cleaned, cleaned))
            result = await cur.fetchone()
            if result:
                return dict(result)

    return None  # 未命中，交给 LLM 补充
```

#### 规则引擎：评级计算

```python
def calculate_overall_grade(matched: list[dict], pet_type: str) -> str:
    """根据命中的配料列表计算整体评级"""

    # 一票否决：有 toxic 级配料直接 F
    if any(item["risk_level"] == "toxic" for item in matched):
        return "F"

    score = 100

    # 扣分项
    danger_count = sum(1 for i in matched if i["risk_level"] == "danger")
    caution_count = sum(1 for i in matched if i["risk_level"] == "caution")
    score -= danger_count * 15
    score -= caution_count * 5

    # 加分项：动物蛋白是否排在前几位（配料表按含量排序）
    first_three = [m for m in matched[:3]]
    animal_protein_top = any(
        m["category"] == "protein_animal" for m in first_three
    )
    if animal_protein_top:
        score += 10

    # 加分项：使用天然抗氧化剂
    has_natural_antioxidant = any(
        "迷迭香" in m.get("name_zh", "") or "生育酚" in m.get("name_zh", "")
        for m in matched
    )
    if has_natural_antioxidant:
        score += 5

    # 映射到等级
    if score >= 90: return "A"
    if score >= 80: return "B+"
    if score >= 70: return "B"
    if score >= 60: return "C+"
    if score >= 50: return "C"
    if score >= 40: return "D"
    return "F"
```

#### 核心处理流程

```python
async def analyze(image_bytes: bytes, pet_type: str = "both"):
    # Step 1: OCR（0.5-2s）
    raw_text = ocr_image(image_bytes)

    # Step 2: 解析配料项（<10ms）
    items = parse_ingredients(raw_text)

    # Step 3: 逐项匹配知识库（<100ms 总计）
    results = []
    for item in items:
        matched = await match_ingredient(item, pool)
        results.append({"raw_name": item, "matched": matched})

    # Step 4: 危险配料硬编码兜底（<10ms）
    async with pool.acquire() as conn:
        async with conn.cursor(aiomysql.DictCursor) as cur:
            for r in results:
                await cur.execute(
                    "SELECT * FROM toxic_overrides WHERE %s LIKE CONCAT('%%', keyword, '%%')",
                    (r["raw_name"],)
                )
                override = await cur.fetchone()
                if override:
                    r["matched"] = r["matched"] or {}
                    r["matched"]["risk_level"] = override["risk_level"]
                    r["matched"]["risk_reason"] = override["reason"]
                    r["matched"]["_source"] = "hardcoded_override"

    # Step 5: 评级计算（<10ms）
    matched_items = [r["matched"] for r in results if r["matched"]]
    grade = calculate_overall_grade(matched_items, pet_type)

    # Step 6: 生成高亮和建议（规则模板，不调 LLM）
    highlights = extract_highlights(matched_items, pet_type)
    risks = extract_risks(matched_items)
    suggestions = generate_suggestions(matched_items, grade, pet_type)

    # Step 7（可选）: 未命中的配料调 LLM 补充
    for r in results:
        if r["matched"] is None:
            r["llm_analysis"] = await llm_analyze_unknown(r["raw_name"])
            # 可选：异步写回知识库

    return {
        "raw_text": raw_text,
        "ingredients": results,
        "overall": {
            "grade": grade,
            "highlights": highlights,
            "risks": risks,
            "suggestions": suggestions
        }
    }
```

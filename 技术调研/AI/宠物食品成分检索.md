背景：
1. 我要做一个宠物专区的宠物食品及其各种添加剂的成分检索的功能，主要能够根据食品配料或者食品本身分析成分以及对宠物的好处和坏处
2.

## 一、可用的公开数据库与 API

### 1. Open Pet Food Facts（⭐ 首选推荐）

| 项目       | 说明                                      |
| -------- | --------------------------------------- |
| **网址**   | https://world.openpetfoodfacts.org      |
| **定位**   | 全球最大的开放宠物食品数据库（Open Food Facts 的姊妹项目）   |
| **数据量**  | 覆盖全球数十万款宠物食品产品                          |
| **数据内容** | 条形码、品牌、配料表、营养成分（蛋白质/脂肪/纤维/水分等）、添加剂、营养评级 |
| **API**  | REST API，支持按条形码查询、分类浏览、关键词搜索            |
| **数据格式** | JSON / CSV / RDF 数据全集可下载                |
| **许可**   | Open Database License (ODbL)，免费使用需署名    |

**常用 API 端点：**
```
# 按条形码查询
GET https://world.openpetfoodfacts.org/api/v0/product/{barcode}.json

# 按分类浏览
GET https://world.openpetfoodfacts.org/category/pet-food.json

# 关键词搜索
GET https://world.openpetfoodfacts.org/cgi/search.pl?search_terms=chicken&json=1
```

**优势：** 数据开放、有 API、支持全量数据下载、社区持续更新
**劣势：** 中国品牌覆盖可能不完整，配料翻译需要额外处理

| 项目       | 说明                            |

| **数据内容** | 原料级别的详细营养成分（氨基酸、脂肪酸、矿物质、维生素等） |
| **API**  | REST API，需免费申请 API Key        |
| **用途**   | 查询单个原料（如鸡肉粉、鱼油、维生素E）的详细营养数据   |

**适用场景：** 当用户输入某个配料名时，用它查询该配料的精确营养成分
**注意：** 主要面向人类食品，但大多数宠物食品原料有重叠

### 核心模块设计

#### 模块 1：食品识别与数据获取
```
输入方式：
  - 条形码扫描 → 调用 Open Pet Food Facts API 获取产品数据
  - 品牌名搜索 → 关键词搜索 + 品牌匹配
  - 配料表文字 → OCR 识别 + NLP 解析配料列表
  - 拍照识别   → 图像识别配料表文字
```

#### 模块 2：配料解析引擎
```
功能：
  - 将配料表文本拆分为单个配料项
  - 配料标准化（"鸡胸肉" → "鸡肉"，"Chicken Breast" → "Chicken"）
  - 配料分类：
    · 主要蛋白质来源（鸡肉、牛肉、鱼肉...）
    · 碳水化合物来源（糙米、玉米、土豆...）
    · 脂肪来源（鸡脂、鱼油...）
    · 添加剂（防腐剂、抗氧化剂、着色剂...）
    · 维生素与矿物质
```

#### 模块 3：成分分析与评估（核心）
```
对每个配料项进行：
  1. 营养价值评估（基于 USDA FDC 数据）
  2. 对宠物（猫/犬）的益处分析
  3. 潜在风险与注意事项
  4. 常见过敏原标记
  5. AAFCO/FEDIAF 合规性检查
```

#### 模块 4：综合报告生成
```
输出：
  - 整体营养评级（A/B/C/D/F）
  - 各配料逐一分析
  - 优势亮点
  - 风险/争议配料高亮
  - 适用宠物类型（猫/犬/年龄段）
  - 改善建议
```

## 三、宠物食品配料知识库的构建

> 配料知识库是整个系统的数据基石。公开 API 只能告诉你"产品里有什么配料"，但无法告诉你"这个配料对猫/犬好不好"。这一层必须自建。

### 3.1 知识库的两种形态

```
形态 A：结构化数据库（规则引擎用）
  → 每个配料一条记录，字段固定，支持精确查询
  → 用于：毒性标记、过敏原判断、评级计算

形态 B：向量知识库（LLM/RAG 用）
  → 每个配料一段专业描述文本，生成 Embedding
  → 用于：自然语言问答、个性化建议生成

推荐：两者同时建设，共用同一份数据源
```

---

### 3.2 配料数据模型设计

#### 核心表：ingredients（配料主表）

```sql
CREATE TABLE ingredients (
    id              SERIAL PRIMARY KEY,
    name_zh         VARCHAR(200) NOT NULL,        -- 中文名：鸡肉
    name_en         VARCHAR(200),                 -- 英文名：Chicken
    aliases         JSONB,                        -- 别名列表：["鸡胸肉","chicken breast","去骨鸡肉"]
    category        VARCHAR(50) NOT NULL,         -- 分类（见下方枚举）
    sub_category    VARCHAR(50),                  -- 子分类
    description     TEXT,                         -- 通用描述
    
    -- 风险评估
    risk_level      VARCHAR(20) DEFAULT 'safe',   -- safe / caution / dangerous / toxic
    risk_reason     TEXT,                         -- 风险原因说明
    
    -- 对猫的影响
    cat_benefit     TEXT,                         -- 对猫的好处
    cat_risk        TEXT,                         -- 对猫的风险
    cat_allergen    BOOLEAN DEFAULT FALSE,        -- 是否猫常见过敏原
    cat_relevance   VARCHAR(20) DEFAULT 'medium', -- high/medium/low（猫对该营养的需求程度）
    
    -- 对犬的影响
    dog_benefit     TEXT,                         -- 对犬的好处
    dog_risk        TEXT,                         -- 对犬的风险
    dog_allergen    BOOLEAN DEFAULT FALSE,        -- 是否犬常见过敏原
    dog_relevance   VARCHAR(20) DEFAULT 'medium', -- high/medium/low
    
    -- 营养标签
    key_nutrients   JSONB,                        -- 主要营养成分 ["蛋白质","维生素B12","锌"]
    nutrient_density VARCHAR(20),                 -- high/medium/low
    
    -- 元数据
    source          VARCHAR(100),                 -- 数据来源标注
    updated_at      TIMESTAMP DEFAULT NOW(),
    verified        BOOLEAN DEFAULT FALSE,        -- 是否经专业审核
    
    UNIQUE(name_zh)
);
```

#### 分类枚举（category 字段）

```
protein_animal      -- 动物蛋白（鸡肉、牛肉、鱼肉、鸡蛋...）
protein_plant       -- 植物蛋白（大豆、豌豆蛋白...）
carb_grain          -- 谷类碳水（糙米、玉米、小麦...）
carb_grain_free     -- 无谷碳水（土豆、红薯、豌豆...）
fat_animal          -- 动物脂肪（鸡脂、牛油...）
fat_plant           -- 植物脂肪（亚麻籽油、椰子油...）
fiber               -- 纤维（甜菜粕、南瓜、车前子壳...）
vitamin             -- 维生素类添加剂
mineral             -- 矿物质类添加剂
preservative        -- 防腐剂（BHA、混合生育酚...）
antioxidant         -- 抗氧化剂
colorant            -- 着色剂
flavor_enhancer     -- 风味增强剂
bind_thickener      -- 粘合剂/增稠剂（卡拉胶、瓜尔胶...）
supplement          -- 功能性补充剂（葡萄糖胺、益生菌...）
other               -- 其他
```

#### 辅助表：ingredient_nutrients（配料营养成分关联表）

```sql
CREATE TABLE ingredient_nutrients (
    id              SERIAL PRIMARY KEY,
    ingredient_id   INT REFERENCES ingredients(id),
    nutrient_name   VARCHAR(100),                -- 营养素名称：粗蛋白质
    nutrient_name_en VARCHAR(100),                -- Protein
    amount_per_100g DECIMAL(10,2),               -- 每100g含量
    unit            VARCHAR(20),                  -- g / mg / μg / IU
    data_source     VARCHAR(100),                 -- USDA FDC / 自测 / 文献
    UNIQUE(ingredient_id, nutrient_name)
);
```

#### 辅助表：ingredient_standards（配料合规标准）

```sql
CREATE TABLE ingredient_standards (
    id              SERIAL PRIMARY KEY,
    ingredient_id   INT REFERENCES ingredients(id),
    standard_body   VARCHAR(50),                  -- AAFCO / FEDIAF / GB(国标)
    allowed_cat     BOOLEAN,                      -- 猫粮中是否允许使用
    allowed_dog     BOOLEAN,                      -- 犬粮中是否允许使用
    max_percentage  DECIMAL(5,2),                 -- 最大允许占比（%）
    notes           TEXT
);
```

### 3.3 数据从哪里来？

#### 第一层：权威文献（优先级最高，直接录入）

| 来源                          | 获取方式           | 覆盖内容             |
| --------------------------- | -------------- | ---------------- |
| **AAFCO 官方配料定义手册**          | 购买/下载 PDF，手动提取 | 所有合法配料名称、定义、使用规范 |
| **FEDIAF 营养指南**             | 官网免费下载         | 猫犬营养需求标准值、安全上限   |
| **中国 GB/T 31216-31217**     | 国标网下载          | 中国猫犬粮营养标准        |
| **WSAVA 营养指南**              | 兽医协会发布         | 宠物营养最佳实践         |
| **Merck Veterinary Manual** | 在线版            | 各配料对猫犬的毒理学数据     |

> **这部分是安全底线，必须人工审核，不能完全依赖 LLM 或爬虫。**
> 建议初始阶段覆盖 **150-200 个核心配料** 即可满足 90% 场景。

#### 第二层：公开数据库（批量导入）

```
USDA FoodData Central
  → 申请免费 API Key
  → 批量查询常见宠物食品配料的营养成分
  → 导入 ingredient_nutrients 表
  
Open Pet Food Facts 数据全集
  → 下载 CSV 数据包
  → 提取所有配料文本 → 去重 → 得到配料名称词表
  → 用于：配料标准化、别名收集、发现新配料
```

#### 第三层：LLM 辅助生成（快速扩量）

```
用 LLM 批量生成初始数据，再用人工审核修正：

Prompt 示例：
---
你是一名宠物营养学专家。请为以下宠物食品配料生成详细分析：
配料名：{name}
请输出 JSON 格式：
{
  "category": "分类",
  "cat_benefit": "对猫的好处...",
  "cat_risk": "对猫的风险...",
  "cat_allergen": true/false,
  "dog_benefit": "对犬的好处...",
  "dog_risk": "对犬的风险...",
  "dog_allergen": true/false,
  "risk_level": "safe/caution/dangerous/toxic",
  "key_nutrients": ["营养素1","营养素2"],
  "aliases": ["别名1","别名2"]
}
---

流程：
  1. 准备配料名列表（从 Open Pet Food Facts 提取去重）
  2. 批量调用 LLM 生成 JSON
  3. 人工审核修正（特别是 risk_level = toxic 的条目必须复核）
  4. 导入数据库
```

#### 第四层：社区贡献 & 持续更新

```
上线后：
  - 用户提交新配料 → 进入待审核队列
  - 兽医/专业人士审核 → 入库
  - 定期与 AAFCO/FEDIAF 新版本同步
```

### 3.4 配料标准化（关键难题）

用户输入和食品包装上的配料名称千奇百怪，必须标准化后才能匹配知识库：

```
标准化流程：

输入文本 → 清洗 → 分词 → 同义词匹配 → 知识库 ID

示例：
  "新鲜去骨鸡胸肉（含鸡肉精华）" 
    → 清洗：去除括号内容 → "新鲜去骨鸡胸肉"
    → 分词提取核心：["鸡肉", "鸡胸肉"]
    → 同义词匹配：aliases 包含 "鸡胸肉"
    → 命中 ingredients.id = 1 (鸡肉)

实现方式：
  - 方案 A：基于 Elasticsearch 的模糊匹配 + 同义词词典
  - 方案 B：基于 LLM 的意图理解（准确但慢、贵）
  - 方案 C：正向最大匹配 + 编辑距离（轻量、够用）
  - 推荐先用方案 C 启动，后期叠加方案 A
```

#### 别名表设计

```sql
CREATE TABLE ingredient_aliases (
    id              SERIAL PRIMARY KEY,
    ingredient_id   INT REFERENCES ingredients(id),
    alias           VARCHAR(200) NOT NULL,        -- "鸡胸肉"
    language        VARCHAR(10) DEFAULT 'zh',      -- zh / en
    source          VARCHAR(50),                   -- manual / opff / user
    UNIQUE(alias, language)
);

-- 建立索引加速匹配
CREATE INDEX idx_alias ON ingredient_aliases(alias);
```

## 四、技术实现建议

### 方案 A：LLM + 规则引擎混合（推荐）

```
架构：
  ┌─ 规则引擎：处理标准化判断（AAFCO标准对比、过敏原匹配、毒性配料标记）
  └─ LLM：处理自然语言解释、个性化建议生成

优点：
  - 准确性高（规则引擎兜底关键安全判断）
  - 灵活（LLM 生成用户友好的解释）
  - 成本可控（规则引擎处理 70% 逻辑，LLM 处理 30%）

技术栈建议：
  - 后端：Node.js / Python (FastAPI)
  - 数据源：Open Pet Food Facts API + 自建配料知识库
  - LLM：Claude API / GPT-4
  - 数据库：PostgreSQL（产品数据） + 向量数据库（配料知识检索）
```

### 方案 B：纯 LLM 方案（快速启动）

```
架构：将配料知识作为 System Prompt / RAG 上下文，直接用 LLM 分析

优点：开发快，初始成本低
缺点：纯 LLM 可能产生幻觉，对安全性判断不够可靠
适用：MVP 阶段、小规模验证
```

### 方案 C：纯规则引擎（安全优先）

```
架构：基于预设规则和数据库查询，无 LLM

优点：结果 100% 确定性，安全
缺点：用户体验差（无自然语言解释），维护成本高（规则需持续更新）
适用：仅做成分查询 + 安全警示的简单工具
```

### Phase 1 — MVP（2-3 周）

## 六、结论

**有没有全量数据库？** 
- ✅ **Open Pet Food Facts** 是最接近"全量"的免费开放宠物食品数据库，有 API，推荐作为主数据源
- ⚠️ 但没有任何一个数据库能覆盖全球所有产品，特别是中国本土品牌覆盖较弱
- 建议：**Open Pet Food Facts 为主 + 自建知识库为辅 + LLM 做智能分析**

**推荐实现路径：**
> **方案 A（LLM + 规则引擎）** 最为可靠，用规则引擎确保安全关键判断的准确性，用 LLM 提供友好的分析报告和个性化建议

背景：
1. 用户拍摄宠物食品包装袋的配料表照片 → OCR 识别配料文字 → 逐项分析每个配料对猫/犬的好处和坏处
2. 不做具体品牌/产品的检索，不查条形码，纯基于配料表做成分分析

---

## 二、系统架构方案

### 核心流程（极简）

```
用户拍照 → OCR 识别配料表 → 配料解析与标准化 → 知识库匹配 → 生成分析报告
```

### 详细流程

```
┌───────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────┐
│ 用户拍照    │     │  OCR 识别     │     │  配料解析与    │     │  分析与报告    │     │          │
│ 配料表     │────▶│  配料表文字   │────▶│  标准化       │────▶│  生成        │────▶│ 展示结果  │
│           │     │              │     │              │     │              │     │          │
└───────────┘     └──────────────┘     └──────┬───────┘     └──────┬───────┘     └──────────┘
                                              │                    │
                                       ┌──────▼───────┐     ┌─────▼──────┐
                                       │  自建配料知识库│     │ LLM + 规则  │
                                       │  (PostgreSQL) │     │ 引擎       │
                                       └──────────────┘     └────────────┘
```

### 三大核心模块

#### 模块 1：OCR 配料表识别

```
输入：用户拍摄的宠物食品包装袋配料表照片
处理：
  - 图片预处理（矫正、增强对比度）
  - OCR 文字识别（中英文混合）
  - 输出配料表原始文本
技术选型：
  - 方案 A：调用云端 OCR API（百度/腾讯/阿里 OCR，中文识别好）
  - 方案 B：开源 PaddleOCR（可私有化部署，免费）
  - 方案 C：直接用多模态 LLM（GPT-4o / Claude）识别图片中的文字
推荐：MVP 用方案 C（多模态 LLM 直接读图），后期可切换方案 B 降本
```

#### 模块 2：配料解析与标准化

```
输入：OCR 识别出的配料表原始文本
  例："配料：新鲜鸡肉(30%)、糙米(20%)、鸡脂(保存混合生育酚)、
       干燥甜菜粕、磷酸氢钙、氯化钾、维生素A补充剂、维生素B12补充剂、
       硫酸锌、硫酸亚铁、BHA、迷迭香提取物"

处理：
  Step 1 — 文本清洗
    - 去除"配料："、"Ingredients:" 等前缀
    - 统一分隔符（中英文逗号、顿号 → 统一分隔）

  Step 2 — 拆分为单个配料项
    → ["新鲜鸡肉(30%)", "糙米(20%)", "鸡脂(保存混合生育酚)", ...]

  Step 3 — 标准化匹配
    "新鲜鸡肉(30%)"        → 鸡肉 (id=1)
    "鸡脂(保存混合生育酚)"   → 鸡脂 (id=34)
    "维生素A补充剂"         → 维生素A (id=102)
    "BHA"                  → BHA (id=89, risk_level=caution)

  Step 4 — 配料分类
    · 动物蛋白 → 鸡肉
    · 谷类碳水 → 糙米
    · 动物脂肪 → 鸡脂
    · 防腐剂   → BHA（⚠️ 标记争议）
```

#### 模块 3：分析报告生成

```
输入：标准化后的配料列表 + 知识库数据
输出：

  📊 整体评级：B+
  🐱 适用宠物：成年猫 | 幼猫 | 全阶段猫

  ✅ 优势配料：
    · 鸡肉（30%）：优质动物蛋白，猫咪必需氨基酸来源
    · 糙米（20%）：易消化的碳水来源，提供持久能量
    · 迷迭香提取物：天然抗氧化剂，安全性好

  ⚠️ 需关注：
    · BHA：合成防腐剂，潜在健康争议，建议选择使用天然抗氧化剂的产品

  📋 逐项分析：
    [每个配料的详细说明...]

  💡 建议：
    · 蛋白质来源单一（仅鸡肉），可轮换不同蛋白源的猫粮
    · 含谷物，如有谷物过敏的猫咪需注意
```

## 三、宠物食品配料知识库的构建

> 配料知识库是整个系统的数据基石。公开 API 只能告诉你"产品里有什么配料"，但无法告诉你"这个配料对猫/犬好不好"。这一层必须自建。

### 3.1 知识库的两种形态

```
形态 A：结构化数据库（规则引擎用）
  → 每个配料一条记录，字段固定，支持精确查询
  → 用于：毒性标记、过敏原判断、评级计算

形态 B：向量知识库（LLM/RAG 用）
  → 每个配料一段专业描述文本，生成 Embedding
  → 用于：自然语言问答、个性化建议生成

推荐：两者同时建设，共用同一份数据源
```

---

### 3.2 配料数据模型设计

#### 核心表：ingredients（配料主表）

```sql
CREATE TABLE ingredients (
    id              SERIAL PRIMARY KEY,
    name_zh         VARCHAR(200) NOT NULL,        -- 中文名：鸡肉
    name_en         VARCHAR(200),                 -- 英文名：Chicken
    aliases         JSONB,                        -- 别名列表：["鸡胸肉","chicken breast","去骨鸡肉"]
    category        VARCHAR(50) NOT NULL,         -- 分类（见下方枚举）
    sub_category    VARCHAR(50),                  -- 子分类
    description     TEXT,                         -- 通用描述
    
    -- 风险评估
    risk_level      VARCHAR(20) DEFAULT 'safe',   -- safe / caution / dangerous / toxic
    risk_reason     TEXT,                         -- 风险原因说明
    
    -- 对猫的影响
    cat_benefit     TEXT,                         -- 对猫的好处
    cat_risk        TEXT,                         -- 对猫的风险
    cat_allergen    BOOLEAN DEFAULT FALSE,        -- 是否猫常见过敏原
    cat_relevance   VARCHAR(20) DEFAULT 'medium', -- high/medium/low（猫对该营养的需求程度）
    
    -- 对犬的影响
    dog_benefit     TEXT,                         -- 对犬的好处
    dog_risk        TEXT,                         -- 对犬的风险
    dog_allergen    BOOLEAN DEFAULT FALSE,        -- 是否犬常见过敏原
    dog_relevance   VARCHAR(20) DEFAULT 'medium', -- high/medium/low
    
    -- 营养标签
    key_nutrients   JSONB,                        -- 主要营养成分 ["蛋白质","维生素B12","锌"]
    nutrient_density VARCHAR(20),                 -- high/medium/low
    
    -- 元数据
    source          VARCHAR(100),                 -- 数据来源标注
    updated_at      TIMESTAMP DEFAULT NOW(),
    verified        BOOLEAN DEFAULT FALSE,        -- 是否经专业审核
    
    UNIQUE(name_zh)
);
```

#### 分类枚举（category 字段）

```
protein_animal      -- 动物蛋白（鸡肉、牛肉、鱼肉、鸡蛋...）
protein_plant       -- 植物蛋白（大豆、豌豆蛋白...）
carb_grain          -- 谷类碳水（糙米、玉米、小麦...）
carb_grain_free     -- 无谷碳水（土豆、红薯、豌豆...）
fat_animal          -- 动物脂肪（鸡脂、牛油...）
fat_plant           -- 植物脂肪（亚麻籽油、椰子油...）
fiber               -- 纤维（甜菜粕、南瓜、车前子壳...）
vitamin             -- 维生素类添加剂
mineral             -- 矿物质类添加剂
preservative        -- 防腐剂（BHA、混合生育酚...）
antioxidant         -- 抗氧化剂
colorant            -- 着色剂
flavor_enhancer     -- 风味增强剂
bind_thickener      -- 粘合剂/增稠剂（卡拉胶、瓜尔胶...）
supplement          -- 功能性补充剂（葡萄糖胺、益生菌...）
other               -- 其他
```

#### 辅助表：ingredient_nutrients（配料营养成分关联表）

```sql
CREATE TABLE ingredient_nutrients (
    id              SERIAL PRIMARY KEY,
    ingredient_id   INT REFERENCES ingredients(id),
    nutrient_name   VARCHAR(100),                -- 营养素名称：粗蛋白质
    nutrient_name_en VARCHAR(100),                -- Protein
    amount_per_100g DECIMAL(10,2),               -- 每100g含量
    unit            VARCHAR(20),                  -- g / mg / μg / IU
    data_source     VARCHAR(100),                 -- USDA FDC / 自测 / 文献
    UNIQUE(ingredient_id, nutrient_name)
);
```

#### 辅助表：ingredient_standards（配料合规标准）

```sql
CREATE TABLE ingredient_standards (
    id              SERIAL PRIMARY KEY,
    ingredient_id   INT REFERENCES ingredients(id),
    standard_body   VARCHAR(50),                  -- AAFCO / FEDIAF / GB(国标)
    allowed_cat     BOOLEAN,                      -- 猫粮中是否允许使用
    allowed_dog     BOOLEAN,                      -- 犬粮中是否允许使用
    max_percentage  DECIMAL(5,2),                 -- 最大允许占比（%）
    notes           TEXT
);
```

| 来源                          | 获取方式           | 覆盖内容             |
| --------------------------- | -------------- | ---------------- |
| **AAFCO 官方配料定义手册**          | 购买/下载 PDF，手动提取 | 所有合法配料名称、定义、使用规范 |
| **FEDIAF 营养指南**             | 官网免费下载         | 猫犬营养需求标准值、安全上限   |

```
  → 下载 CSV 数据包
```

#### 第三层：LLM 辅助生成（快速扩量）

```
用 LLM 批量生成初始数据，再用人工审核修正：

Prompt 示例：
---
你是一名宠物营养学专家。请为以下宠物食品配料生成详细分析：
配料名：{name}
请输出 JSON 格式：
{
  "category": "分类",
  "cat_benefit": "对猫的好处...",
  "cat_risk": "对猫的风险...",
  "cat_allergen": true/false,
  "dog_benefit": "对犬的好处...",
  "dog_risk": "对犬的风险...",
  "dog_allergen": true/false,

流程：
```

### 3.4 配料标准化（关键难题）

用户输入和食品包装上的配料名称千奇百怪，必须标准化后才能匹配知识库：

```
标准化流程：

输入文本 → 清洗 → 分词 → 同义词匹配 → 知识库 ID

示例：
  "新鲜去骨鸡胸肉（含鸡肉精华）" 
    → 清洗：去除括号内容 → "新鲜去骨鸡胸肉"
    → 分词提取核心：["鸡肉", "鸡胸肉"]
    → 同义词匹配：aliases 包含 "鸡胸肉"
    → 命中 ingredients.id = 1 (鸡肉)

实现方式：
  - 方案 A：基于 Elasticsearch 的模糊匹配 + 同义词词典
  - 方案 B：基于 LLM 的意图理解（准确但慢、贵）
  - 方案 C：正向最大匹配 + 编辑距离（轻量、够用）
  - 推荐先用方案 C 启动，后期叠加方案 A
```

#### 别名表设计

```sql
CREATE TABLE ingredient_aliases (
    id              SERIAL PRIMARY KEY,
    ingredient_id   INT REFERENCES ingredients(id),
    alias           VARCHAR(200) NOT NULL,        -- "鸡胸肉"
    language        VARCHAR(10) DEFAULT 'zh',      -- zh / en
    source          VARCHAR(50),                   -- manual / opff / user
    UNIQUE(alias, language)
);

-- 建立索引加速匹配
CREATE INDEX idx_alias ON ingredient_aliases(alias);
```

```
  ──────────────────────────────────────────────
  其中 LLM 生成初始数据：2-3 天
  人工审核 + 修正：5-7 天（可并行）
```

## 四、技术实现建议

### 方案 A：多模态 LLM + 规则引擎混合（推荐）

```
架构：
  ┌─ 多模态 LLM：直接读取配料表照片，输出配料列表文字
  ┌─ 规则引擎：基于知识库做确定性判断（毒性标记、过敏原、评级计算）
  └─ LLM：结合知识库数据 + 规则引擎结论，生成用户友好的分析报告

技术栈建议：
  - OCR / 图片理解：GPT-4o / Claude 多模态（MVP）
                      PaddleOCR（后期降本）
  - 后端：Node.js / Python (FastAPI)
  - 知识库：PostgreSQL（结构化数据） + 向量数据库（RAG 检索）
  - LLM：Claude API / GPT-4（报告生成）
```

### 方案 B：纯多模态 LLM（最快启动）

```
架构：直接将配料表照片 + 预置配料知识 Prompt 发给多模态 LLM，一步出结果

优点：开发极快（几天可上线），无需自建数据库
缺点：
  - 纯 LLM 可能产生幻觉（漏判有毒配料或误判安全性）
  - 无法精确控制评级逻辑
  - 每次调用成本较高
适用：验证阶段、小规模试水
```

### 方案 C：OCR + 纯规则引擎（无 LLM）

```
架构：OCR 提取文字 → 配料标准化 → 数据库精确匹配 → 模板化输出

优点：结果 100% 确定性，成本最低
缺点：输出死板，无法处理知识库外的配料，用户体验差
适用：预算极低或对 LLM 不信任的场景
```

**推荐路径：先用方案 B 验证需求（1 周），再切换到方案 A（3-4 周）。**

```
1. **识别配料表**：准确读出照片中所有配料文字
2. **逐项分析**：对每个配料进行以下评估：
   - 该配料是什么（简要说明）

   - 对犬的影响（好处/风险/注意）
   - 安全评级：✅ 安全 / ⚠️ 需关注 / 🚫 危险
3. **整体评估**：
   - 这款食品的整体质量评级（A+ 到 F）
   - 主要优势和亮点
   - 需要关注的风险点
   - 适合的宠物类型和年龄段
4. **建议**：给出改善建议或替代方案

输出格式为 JSON：
{
  "ingredients": [

    }
  ],
  "overall": {
    "grade": "A+ ~ F",
    "highlights": ["亮点1", "亮点2"],
    "risks": ["风险1", "风险2"],
```

```
  ✅ 每个配料都有安全评级
  ✅ 有毒配料（木糖醇、洋葱粉等）不会漏判
  ✅ 输出 JSON 格式稳定可解析
```

### Day 2-3 — 后端 API

**目标：** 封装一个 HTTP 接口，接收图片返回分析结果

#### 技术选型（选最熟悉的）

```
Python (FastAPI) 或 Node.js (Express)

依赖：
  - HTTP 框架
  - LLM SDK（openai / anthropic）
  - 图片 base64 编码

不需要：
  ✗ 数据库
  ✗ OCR 库
  ✗ 向量数据库
  ✗ 消息队列
```

#### API 设计

```
POST /api/analyze

Request (multipart/form-data):
  - image: 配料表照片（JPG/PNG）
  - pet_type: "cat" | "dog" | "both"（可选，默认 both）

Response (JSON):
  {
    "success": true,
    "data": {
      "ingredients": [...],      // 逐项分析
      "overall": {...},           // 整体评级
      "suggestions": [...]        // 建议
    }
  }
```

#### 关键代码逻辑

```
伪代码：

1. 接收图片 → base64 编码
2. 构造多模态消息：
     system = System Prompt（上述模板）
     user   = [image(base64), "请分析这张配料表"]
3. 调用 LLM API（GPT-4o / Claude）
4. 解析返回的 JSON
5. 补充硬编码安全检查（兜底）：
     - 检查配料列表中是否包含已知的极度危险配料
     - 如果 LLM 遗漏了危险标记，强制覆盖为 danger
6. 返回结果
```

#### 硬编码安全兜底（关键！）

```python
# 纯 LLM 可能漏判的极度危险配料，硬编码强制拦截
TOXIC_INGREDIENTS = {
    "木糖醇": "对犬极度危险，可致死",
    "xylitol": "对犬极度危险，可致死",
    "洋葱": "对猫犬均有溶血性毒性",
    "onion": "对猫犬均有溶血性毒性",
    "巧克力": "茶碱/咖啡因中毒",
    "葡萄": "对犬可致急性肾衰竭",
    "raisin": "对犬可致急性肾衰竭",
    "乙氧基喹啉": "多国已禁用的合成抗氧化剂",
}

# 在 LLM 返回结果后，额外扫描一遍
for item in result["ingredients"]:
    for toxic_name, reason in TOXIC_INGREDIENTS.items():
        if toxic_name in item["name"].lower():
            item["safety"] = "danger"
            item["safety_detail"] = f"⚠️ {reason}"
```

### MVP 总结

```

  ✗ 不建数据库（知识全压在 Prompt 里）
```

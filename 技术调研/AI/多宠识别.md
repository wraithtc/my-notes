# 多宠识别技术调研

## 背景

1. 我提供平台+app+设备端到端服务
2. 多宠识别应用设备为可视喂食器，也就是带摄像头的喂食器
3. 场景为用户家里养了多只宠物时，通过可视喂食器的摄像头，可以识别是哪只宠物过来进食，进食了多长时间
4. 刚开始我的用户不多，几百/几千，未来几年可能会到万级

**识别目标**: 猫和狗的**个体识别**（区分是哪只宠物，而非品种分类）

**部署方式**: 全部服务端部署，设备端只负责采集和上传

- **GitHub**: [github.com/GuillaumeMougeot/DogFaceNet](https://github.com/GuillaumeMougeot/DogFaceNet)
- **技术**: FaceNet + Triplet Loss + ResNet
- **特点**: 专门针对**狗**的面部识别，代码清晰易上手
- **注意**: 主要针对狗，猫需要适配
- **教程**: [CSDN解析](https://blog.csdn.net/gitblog_00391/article/details/146801588)

- **[Applying DogFaceNet to Cat Face Recognition](https://medium.com/@schatzki.mcclain/applying-dogfacenet-to-cat-face-recognition-task-58ffc01e5018)**: 将DogFaceNet方法应用于猫脸识别
- 某公司声称猫脸识别准确率达到**98%**

### 3. 核心算法流程

#### Step 1: 猫狗检测（YOLOv8）
```python
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
results = model.predict(image, classes=[15, 16])  # 15=cat, 16=dog

# 获取宠物边界框和类别
for box in results[0].boxes:
    x1, y1, x2, y2 = box.xyxy[0]
    cls = int(box.cls[0])  # 0=cat, 1=dog in custom model
    pet_crop = image[int(y1):int(y2), int(x1):int(x2)]
```

#### Step 2: 面部特征提取（PetFace/ArcFace）
```python
# PetFace 同时支持猫和狗的面部特征提取
# 特征向量维度: 512维 或 128维

embedding = petface_model.extract_feature(pet_face)  # shape: (512,)
```

#### Step 3: 向量匹配
```python
from sklearn.metrics.pairwise import cosine_similarity

# 在用户宠物库中查询最相似的宠物
similarities = cosine_similarity(query_embedding, user_pet_embeddings)
best_match_idx = np.argmax(similarities)

# 设置阈值，低于阈值认为是新宠物或识别失败
if similarities[0][best_match_idx] > 0.8:
    return user_pets[best_match_idx]
else:
    return "unknown"
```

### 6. 模型推理加速

#### 📦 ONNX 导出

**ONNX (Open Neural Network Exchange)** 是一种开放的模型格式标准。

| 作用 | 说明 |
|------|------|
| **模型标准化** | 将 PyTorch/TensorFlow 等框架训练的模型转换为统一格式 |
| **跨框架兼容** | 一次导出，可在多种推理引擎上运行（ONNX Runtime、TensorRT、OpenVINO等） |
| **解耦训练与推理** | 训练用 PyTorch，部署用更轻量的推理引擎 |

典型流程：
```python
# PyTorch 模型导出为 ONNX
import torch
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
model.export(format='onnx')  # 生成 yolov8n.onnx
```

优势：
- ✅ 脱离 PyTorch 依赖，部署更轻量
- ✅ 为后续 TensorRT 加速做准备
- ✅ 模型可被多种工具链支持

#### ⚡ TensorRT 加速

**TensorRT** 是 NVIDIA 专为 GPU 推理优化的加速库。

| 作用 | 说明 |
|------|------|
| **层融合** | 合并多个计算层（如 Conv+BN+ReLU → 单层），减少内存读写 |
| **精度校准** | FP32 → FP16/INT8 量化，速度提升 2-4 倍，精度损失可控 |
| **内核自动调优** | 针对特定 GPU 选择最优计算内核 |
| **动态张量显存** | 优化显存使用，支持更大 batch |

性能对比示例：
```
PyTorch (FP32):     45ms / frame
ONNX Runtime:       30ms / frame
TensorRT (FP16):    8ms / frame   ← 5-6倍提升
TensorRT (INT8):    4ms / frame   ← 10倍提升
```

典型流程：
```bash
# ONNX 转 TensorRT 引擎
trtexec --onnx=yolov8n.onnx --saveEngine=yolov8n.trt --fp16
```

#### 🔄 完整优化链路

```
PyTorch 模型 (.pt)
       ↓
    ONNX 导出  ← 标准化，脱离训练框架
       ↓
  ONNX 模型 (.onnx)
       ↓
  TensorRT 编译  ← GPU 专属优化
       ↓
 TensorRT 引擎 (.trt)
       ↓
   高速推理 (毫秒级)
```

#### 在本场景下的价值

| 指标 | 未优化 | TensorRT 优化后 |
|------|--------|-----------------|
| 单帧延迟 | 40-60ms | 5-10ms |
| 吞吐量 | 15-25 FPS | 100+ FPS |
| GPU显存 | 2-3GB | 0.5-1GB |
| 服务器成本 | 需要 T4/A10 | 可用更小 GPU |

**实际意义**：
- 同样的 GPU 服务器可处理更多并发请求
- 用户增长时不必线性增加服务器成本
- 响应更快，用户体验更好

**建议**：先做 ONNX 导出（简单快速，立即可加速 20-30%），再上 TensorRT（需要额外开发，但加速 2-5 倍）

### 7. PetFace 使用详解

> ⚠️ **注意**：PetFace 的数据集、代码和预训练模型**仅限非商业研究用途**

#### PetFace 是什么？

PetFace **不仅是数据集**，它是一个完整的动物面部识别方案：

| 组件 | 内容 | 获取方式 |
|------|------|----------|
| **数据集** | 257K 个体，13 个动物家族 | 填写 Google Form 申请 |
| **预训练模型** | ArcFace 特征提取模型 | Google Drive 下载 |
| **训练代码** | 训练自己的模型 | GitHub 仓库 |
| **推理代码** | Re-ID / Verification | GitHub 仓库 |

#### 如何使用 PetFace 提取面部特征

**Step 1: 下载预训练模型**

从 Google Drive 下载 ArcFace 预训练权重：
- `pretrained/arcface/cat.pt` - 猫专用
- `pretrained/arcface/dog.pt` - 狗专用
- `pretrained/arcface/unified.pt` - 统一模型（推荐）

**Step 2: 面部对齐（关键步骤）**

PetFace 需要先进行面部对齐，使用 AnyFace 检测 5 个关键点：

```bash
# 对齐你的图像
python3 src/face_align.py \
    --tgt /path/to/your/keypoints.npy \
    --img /path/to/your/image.jpeg \
    --src keypoints/cat_src.npy \
    --out /path/to/output/aligned.jpg
```

**Step 3: 特征提取**

```python
import torch
from models.arcface import ArcFace

# 加载预训练模型
model = ArcFace(backbone='ir50', embedding_size=512)
model.load_state_dict(torch.load('pretrained/arcface/cat.pt'))
model.eval()

# 提取特征
with torch.no_grad():
    embedding = model(aligned_face_image)  # shape: (512,)

# 用于向量匹配
from sklearn.metrics.pairwise import cosine_similarity
similarity = cosine_similarity([embedding], known_embeddings)
```

**Step 4: Re-Identification（个体识别）**

```bash
# 在宠物库中识别个体
CUDA_VISIBLE_DEVICES=0 python3 src/reidentification.py \
    -m arcface \
    -w pretrained/arcface/cat.pt \
    -i data/your_pets.csv \
    -o results/reidentification.csv

# 计算 Top-K 准确率
python3 src/compute_topk_acc.py --topk 5 -i results/reidentification.csv
```

#### 实际部署流程

```
原始图像 (喂食器摄像头)
       ↓
   YOLO 检测宠物位置
       ↓
   裁剪宠物区域
       ↓
   AnyFace 检测 5 个面部关键点
       ↓
   PetFace 面部对齐
       ↓
   ArcFace 提取 512 维特征向量
       ↓
   向量数据库匹配 (Milvus/Faiss)
       ↓
   返回匹配的宠物 ID
```

#### ⚠️ 商业使用限制

PetFace **仅限非商业研究用途**。如果你要商业部署，有两个选择：

1. **使用 PetFace 数据训练自己的模型**
   - 数据集同样仅限研究用途
   - 需要自己收集商业可用的训练数据

2. **替代方案**
   - 使用 DogFaceNet（MIT 许可证，商业友好）
   - 使用商业 API（快瞳科技等）
   - 自己收集数据训练 ArcFace 模型

## 三、方案对比与建议

### 场景分析

- **识别目标**: 猫和狗的个体识别
- **用户规模**: 初期几百/几千 → 未来万级
- **设备**: 可视喂食器（有摄像头）
- **场景**: 多宠家庭，识别进食个体和时长
- **部署**: 全部服务端

### 推荐方案

#### 初期阶段（用户<3000）
**建议：付费API - 快瞳科技**

| 方案 | 服务商 | 支持范围 | 预估月成本 |
|------|--------|----------|-----------|
| 个体识别 | **快瞳科技** | ✅ 猫+狗 | ¥200-500 |

**为什么不选旷视？** 旷视只支持狗（鼻纹识别），不支持猫。

理由：
- 快速验证产品需求
- 无需AI研发投入
- 成本可控

#### 增长阶段（用户3000-20000）
**建议：自研模型 + 服务端部署**

技术路线：
1. 使用 **PetFace** 预训练模型（同时支持猫狗）
2. 收集喂食器场景数据微调
3. 部署到云服务器（推荐GPU实例）
4. 逐步从API迁移到自研服务

理由：
- API成本开始显著
- 用户数据积累，可训练定制模型
- 产品需求已验证，值得投入研发

#### 成熟阶段（用户>20000）
**建议：自研模型 + 服务端优化**

技术路线：
1. 模型优化（ONNX/TensorRT加速）
2. 多实例部署 + 负载均衡
3. 持续迭代优化

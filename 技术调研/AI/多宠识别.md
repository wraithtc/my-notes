# 多宠识别技术调研

## 背景

1. 我提供平台+app+设备端到端服务
2. 多宠识别应用设备为可视喂食器，也就是带摄像头的喂食器
3. 场景为用户家里养了多只宠物时，通过可视喂食器的摄像头，可以识别是哪只宠物过来进食，进食了多长时间
4. 刚开始我的用户不多，几百/几千，未来几年可能会到万级

**识别目标**: 猫和狗的**个体识别**（区分是哪只宠物，而非品种分类）

**部署方式**: 全部服务端部署，设备端只负责采集和上传

## 二、开源自研方案（服务端部署）

### 1. 核心开源项目

#### 🏆 PetFace (ECCV 2024 Oral) - 最推荐
- **GitHub**: [github.com/mapooon/PetFace](https://github.com/mapooon/PetFace)
- **论文**: [ECCV 2024](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/02660.pdf)
- **数据集**: 257,484 个动物个体，**13个动物家族（含猫、狗）**，319个品种
- **特点**: 目前最大规模的动物面部识别数据集和基准，SOTA性能，**同时支持猫和狗**

#### DogFaceNet
- **GitHub**: [github.com/GuillaumeMougeot/DogFaceNet](https://github.com/GuillaumeMougeot/DogFaceNet)
- **技术**: FaceNet + Triplet Loss + ResNet
- **特点**: 专门针对**狗**的面部识别，代码清晰易上手
- **注意**: 主要针对狗，猫需要适配
- **教程**: [CSDN解析](https://blog.csdn.net/gitblog_00391/article/details/146801588)

#### 猫脸识别适配
- **[Applying DogFaceNet to Cat Face Recognition](https://medium.com/@schatzki.mcclain/applying-dogfacenet-to-cat-face-recognition-task-58ffc01e5018)**: 将DogFaceNet方法应用于猫脸识别
- 某公司声称猫脸识别准确率达到**98%**

#### 其他相关项目
| 项目 | 链接 | 特点 |
|------|------|------|
| Pets Face Recognition | [GitHub](https://github.com/MarQuisCheshire/Pets-Face-Recognition) | 猫狗面部检测+识别 |

#### 技术栈选型

| 组件 | 推荐方案 | 备选方案 |
|------|----------|----------|
| **检测模型** | YOLOv8/YOLOv11 | YOLOv9, RT-DETR |
| **识别模型** | **PetFace**（猫狗通用） | DogFaceNet（仅狗） |

| **关系数据库** | PostgreSQL | MySQL, MongoDB |

### 3. 核心算法流程

#### Step 1: 猫狗检测（YOLOv8）
```python
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
results = model.predict(image, classes=[15, 16])  # 15=cat, 16=dog

# 获取宠物边界框和类别
for box in results[0].boxes:
    x1, y1, x2, y2 = box.xyxy[0]
    cls = int(box.cls[0])  # 0=cat, 1=dog in custom model
    pet_crop = image[int(y1):int(y2), int(x1):int(x2)]
```

#### Step 2: 面部特征提取（PetFace/ArcFace）
```python
# PetFace 同时支持猫和狗的面部特征提取
# 特征向量维度: 512维 或 128维

embedding = petface_model.extract_feature(pet_face)  # shape: (512,)
```

#### Step 3: 向量匹配
```python
from sklearn.metrics.pairwise import cosine_similarity

# 在用户宠物库中查询最相似的宠物
similarities = cosine_similarity(query_embedding, user_pet_embeddings)
best_match_idx = np.argmax(similarities)

# 设置阈值，低于阈值认为是新宠物或识别失败
if similarities[0][best_match_idx] > 0.8:
    return user_pets[best_match_idx]
else:
    return "unknown"
```

### 5. 自研方案开发路径

#### Phase 1: MVP验证（2-4周）
1. 使用预训练YOLOv8做猫狗检测
2. 使用**PetFace**预训练模型做特征提取（同时支持猫狗）
3. 搭建简单的FastAPI服务验证可行性
4. 使用Faiss做向量检索

#### Phase 2: 系统搭建（1-2月）
1. 收集喂食器场景数据（摄像头视角的猫狗图片）
2. 微调检测模型（适应特定角度/光照）
3. 针对喂食器场景微调识别模型
4. 部署向量数据库（Milvus/Qdrant）
5. 搭建完整的识别Pipeline

#### Phase 3: 优化迭代（持续）
1. 模型优化（ONNX导出、TensorRT加速）
2. 建立宠物注册流程（用户上传宠物照片建档）
3. 持续收集bad case优化模型
4. 增加多宠物同时进食识别能力

## 三、方案对比与建议

### 场景分析

- **识别目标**: 猫和狗的个体识别
- **用户规模**: 初期几百/几千 → 未来万级
- **设备**: 可视喂食器（有摄像头）
- **场景**: 多宠家庭，识别进食个体和时长
- **部署**: 全部服务端

### 推荐方案

#### 初期阶段（用户<3000）
**建议：付费API - 快瞳科技**

| 方案 | 服务商 | 支持范围 | 预估月成本 |
|------|--------|----------|-----------|
| 个体识别 | **快瞳科技** | ✅ 猫+狗 | ¥200-500 |

**为什么不选旷视？** 旷视只支持狗（鼻纹识别），不支持猫。

理由：
- 快速验证产品需求
- 无需AI研发投入
- 成本可控

#### 增长阶段（用户3000-20000）
**建议：自研模型 + 服务端部署**

技术路线：
1. 使用 **PetFace** 预训练模型（同时支持猫狗）
2. 收集喂食器场景数据微调
3. 部署到云服务器（推荐GPU实例）
4. 逐步从API迁移到自研服务

理由：
- API成本开始显著
- 用户数据积累，可训练定制模型
- 产品需求已验证，值得投入研发

#### 成熟阶段（用户>20000）
**建议：自研模型 + 服务端优化**

技术路线：
1. 模型优化（ONNX/TensorRT加速）
2. 多实例部署 + 负载均衡
3. 持续迭代优化

### 成本估算（服务端部署）

| 方案 | 初期投入 | 月度成本(1万用户) | 月度成本(5万用户) |
|------|----------|-------------------|-------------------|
| 付费API（快瞳） | ¥0 | ¥3000-5000 | ¥15000-25000 |
| 自研云端 | ¥10-20万 | ¥2000-4000 | ¥6000-10000 |

**自研方案月度成本构成**（1万用户，假设每用户每天10次识别）：
- GPU服务器（T4/A10）: ¥1500-3000
- 数据库+存储: ¥300-500
- 带宽: ¥200-500

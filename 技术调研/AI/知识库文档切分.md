# RAG 知识库文档切分技术调研

> 调研日期：2026-03-17
> 标签：#RAG #知识库 #文档切分 #向量检索

## 一、概述

文档切分（Document Chunking）是 RAG 系统中最关键的预处理步骤之一，直接影响知识检索精度与 LLM 输出效果。根据研究，切分策略的差异可导致高达 9% 的召回率差距。

### RAG 工作流程

1. **知识库构建**：文档分割 → 生成向量嵌入 → 存储至向量数据库
2. **实时检索**：查询向量化 → 检索 Top-K 相关文本块
3. **生成响应**：检索结果与查询拼接 → 输入 LLM 生成答案

---

## 二、切分策略分类框架

根据 2026 年最新学术论文《Beyond Chunk-Then-Embed》，切分策略可沿两个维度分类：

### 维度 1：分割方法（Segmentation Methods）

| 类别 | 方法 | 特点 |
|------|------|------|
| **结构化方法** | 固定尺寸、句子、段落 | 依赖文档显式布局，高效简单 |
| **语义感知方法** | 语义切分、LLM 引导 | 利用语言理解识别逻辑分割点 |

### 维度 2：嵌入-切分顺序（Embedding-Chunking Ordering）

| 范式 | 描述 | 优缺点 |
|------|------|--------|
| **预嵌入切分 (Pre-embedding)** | 先切分再分别嵌入 | 简单可扩展，但忽略跨块上下文 |
| **后嵌入切分 (Late/Contextualized)** | 先嵌入整文档再切分 | 保留全局上下文，但需长上下文模型 |

---

## 三、七大切分策略详解

### 1. 固定尺寸切分 (Fixed-size Chunking)

最直观的方法，按预定义字符/词元数量统一分割。

```python
from langchain.text_splitter import CharacterTextSplitter
splitter = CharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,  # 关键重叠区
    separator="\n"
)
chunks = splitter.split_documents(docs)
```

**优点**：实现简单、批处理友好、无计算开销
**缺点**：打断语义流、重要信息可能分散到不同块
**适用场景**：原型验证、内容均匀的文档

---

### 2. 递归切分 (Recursive Chunking) ⭐推荐默认

按分隔符层级依次尝试分割（段落 → 行 → 句子 → 词）。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=50,
    separators=["\n\n", "\n", ". ", " ", ""]
)
```

**优点**：保持语言自然流畅、适应不同内容类型
**缺点**：块大小不固定、需了解内容结构
**推荐配置**：400-512 tokens，10-20% 重叠
**研究数据**：Chroma 测试中达到 88-89% 召回率

---

### 3. 语义切分 (Semantic Chunking)

基于相邻句子嵌入相似度检测主题转换点。

```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

semantic_splitter = SemanticChunker(
    embeddings=OpenAIEmbeddings(model="text-embedding-3-small"),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=95
)
```

**优点**：语义连贯性好、检测细微主题转换
**缺点**：计算昂贵（每句需嵌入）、阈值需调优
**研究数据**：比递归切分高 2-9% 召回率，LLM增强版达 0.919

---

### 4. 文档结构切分 (Structure-based Chunking)

利用文档固有结构（标题、章节、段落）定义块边界。

```python
from bs4 import BeautifulSoup

def html_chunking(html):
    soup = BeautifulSoup(html, 'html.parser')
    chunks = []
    for section in soup.find_all(['h1', 'h2', 'h3']):
        # 按标题分组内容
        ...
    return chunks
```

**优点**：保持结构完整性、与文档逻辑对齐
**缺点**：假设文档有清晰结构、块长度可能超出限制

---

### 5. 页面级切分 (Page-level Chunking)

将 PDF 每页作为独立块，适用于分页文档。

```python
from unstructured.partition.pdf import partition_pdf
from unstructured.chunking.title import chunk_by_title

elements = partition_pdf(filename="sample.pdf", strategy="hi_res")
chunks = chunk_by_title(elements, multipage_sections=False)
```

**优点**：保持页面上下文、处理表格/图表自然
**缺点**：仅适用于分页文档、块大小不均
**研究数据**：NVIDIA 2024 基准测试中获胜（0.648 准确率，最低方差）

---

### 6. LLM 智能切分 (LLM-based Chunking)

使用 LLM 分析文档结构并决定切分点。

```python
# GPT-4 提示词设计
prompt = """你是一位专业文本分析师，请根据语义完整性将以下文档分割为多个段落块：
要求：
1. 每个块包含完整语义单元
2. 最大长度不超过 512 token
3. 输出 JSON 格式：{"chunks": ["text1", "text2"]}

文档内容：{document_text}"""
```

**优点**：语义准确性最高、可生成块摘要
**缺点**：计算成本最高、延迟大、需 LLM 访问
**适用场景**：高价值内容、复杂结构文档

#### LumberChunker

专门的长篇叙述文档分割方法，直接提示 LLM 在检测到主题转换的段落间插入断点。

**研究结论**：在文档内检索（In-document）任务中表现最佳

---

### 7. Late Chunking (后嵌入切分) 🆕

2024 年 Jina AI 提出，颠覆传统顺序：先对整个文档做 Transformer 前向传播，再应用切分边界。

```python
from langchain_jina import LateChunkEmbeddings

embeddings = LateChunkEmbeddings(
    jina_api_key=os.getenv("JINA_API_KEY"),
    model_name="jina-embeddings-v3"
)
vectors = embeddings.embed_documents([
    "Berlin is the capital...",
    "Its more than 3.85 million..."
])
```

**原理**：
1. Tokenize 整个文档（至模型上下文窗口）
2. 完整 Token 序列通过所有 Transformer 层
3. 映射切分边界到 Token 级嵌入
4. 均值池化生成最终块向量

**优点**：块嵌入携带完整文档上下文、可与任何边界策略组合
**缺点**：需均值池化模型、受上下文窗口限制（jina-v3 为 8192 tokens）

## 五、2026 年最新研究发现

### arXiv 论文《Beyond Chunk-Then-Embed》核心结论

#### 任务依赖性
- **跨语料库检索 (In-corpus)**：结构化方法（段落、固定尺寸）优于 LLM 引导方法
- **文档内检索 (In-document/Needle-in-haystack)**：LumberChunker 表现最佳

#### Late Chunking 效果
- 对跨语料库检索：普遍提升，LLM 引导方法收益最大
- 对文档内检索：**一致降低**（因块嵌入编码更广泛的文档主题，降低同文档内块的区分度）

#### 块大小影响
- 与文档内检索有效性：中等相关（r=0.41~0.57）
- 与跨语料库检索有效性：弱相关（r=0.08~0.18）

### 其他基准数据

| 研究 | 最佳策略 | 准确率/召回率 |
|------|---------|--------------|
| NVIDIA 2024 | 页面级切分 | 0.648 准确率 |
| Chroma Research | LLM 语义切分 | 0.919 召回率 |
| Vecta 2026 | 递归 512-token | 69% 准确率 |
| MDPI Bioengineering 2025 | 自适应主题切分 | 87% vs 13%（固定尺寸） |

## 六、实践决策框架

### 默认推荐

```
策略：RecursiveCharacterTextSplitter
配置：400-512 tokens，10-20% 重叠
分隔符：["\n\n", "\n", ". ", " ", ""]
```

### 场景化选择

| 你的情况 | 推荐策略 | 原因 |
|---------|---------|------|
| PDF 文档（报告、表格） | 页面级切分 | NVIDIA 基准最佳，保持表格完整 |
| 准确性优先，预算充足 | 语义切分 | 召回率提升 2-9% |
| 预算紧张，追求速度 | 固定尺寸 | 实现最快，无计算开销 |
| 代码文件 | 递归 + 代码分隔符 | 保持函数/类边界 |
| 高价值内容，实验性质 | LLM 切分 | 上下文感知，动态适应 |
| 长文档、跨块引用多 | Late Chunking | 保留全局上下文 |

### 查询类型调优

| 查询类型 | 推荐块大小 |
|---------|-----------|
| 事实查询（人名、日期） | 256-512 tokens |
| 分析查询（解释、比较） | 1024+ tokens |
| 混合查询 | 400-512 tokens（平衡） |

## 七、完整 RAG 管道示例

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_pinecone import PineconeVectorStore

# 1. 配置切分器
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    separators=["\n\n", "\n", ". ", " ", ""]
)

# 2. 切分文档
chunks = splitter.split_documents(documents)

# 3. 嵌入并存储
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = PineconeVectorStore(index=index, embedding=embeddings)
vector_store.add_documents(chunks)

# 4. 查询
results = vector_store.similarity_search(query, k=3)
```

## 八、未来趋势

1. **混合策略**：根据文档类型路由到不同切分方法
2. **Agentic Chunking**：Agent 动态选择每个文档的最佳策略
3. **多层级切分**：摘要层 + 细节层，适应不同查询粒度
4. **知识结构化**：切分后 LLM 生成多级树状目录摘要（章→节→子节→关键段落）

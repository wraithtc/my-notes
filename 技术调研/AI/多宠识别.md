# 多宠识别技术调研

## 背景

1. 我提供平台+app+设备端到端服务
2. 多宠识别应用设备为可视喂食器，也就是带摄像头的喂食器
3. 场景为用户家里养了多只宠物时，通过可视喂食器的摄像头，可以识别是哪只宠物过来进食，进食了多长时间
4. 刚开始我的用户不多，几百/几千，未来几年可能会到万级

### 2. 技术架构选型

#### 方案A：云端推理架构
```
[喂食器摄像头] → [上传图片到云端] → [云服务器推理] → [返回识别结果] → [App展示]
```

**技术栈**：
- **检测模型**: YOLOv8/YOLOv9（宠物检测+定位）
- **识别模型**: PetFace / DogFaceNet / 自训练ArcFace
- **后端**: Python (FastAPI/Flask) + PyTorch/ONNX Runtime
- **存储**: PostgreSQL/MongoDB（宠物特征向量+元数据）

#### 方案B：端侧推理架构（推荐）
```
[喂食器摄像头] → [本地模型推理] → [上传识别结果] → [云端存储+同步] → [App展示]
```

**技术栈**：
- **硬件平台**:
  - 树莓派5 + USB摄像头（性价比高，实时检测85%+准确率）
  - Jetson Nano（GPU加速，更高性能）
- **检测模型**: YOLOv8-nano（轻量化，实时性好）
- **识别模型**: MobileNet-ArcFace（量化后的轻量模型）
- **部署工具**: ONNX Runtime / TensorRT / TFLite

#### 方案C：混合架构
```
[喂食器摄像头] → [本地检测+特征提取] → [上传特征向量] → [云端匹配] → [返回结果]
```

**优点**: 保护隐私（图片不上传），减少带宽，云端集中管理

### 3. 核心算法详解

#### 检测阶段：宠物面部检测
```python
# YOLOv8 宠物检测示例
from ultralytics import YOLO

model = YOLO('yolov8n.pt')  # nano版本，适合端侧部署
results = model.predict(image, classes=[15, 16])  # 15=cat, 16=dog
```

#### 识别阶段：面部特征提取
核心技术路线：**FaceNet/ArcFace + Triplet Loss**

```python
# Triplet Loss 原理
# 输入：Anchor(当前宠物) + Positive(同一宠物其他照片) + Negative(其他宠物)
# 目标：minimize d(anchor, positive), maximize d(anchor, negative)

loss = max(0, d(a, p) - d(a, n) + margin)
```

### 5. 自研方案开发路径

#### Phase 1: MVP验证（2-4周）
1. 使用预训练YOLOv8做宠物检测
2. 使用DogFaceNet/PetFace预训练模型做特征提取
3. 搭建简单的云端API验证可行性

#### Phase 2: 定制优化（1-2月）
1. 收集用户场景数据（喂食器摄像头视角）
2. 微调检测模型（适应特定角度/光照）
3. 训练自定义识别模型（用Triplet Loss）
4. 建立宠物特征向量数据库

#### Phase 3: 端侧部署（1-2月）
1. 模型量化（INT8/FP16）
2. 移植到喂食器硬件平台
3. 优化推理速度（目标<100ms）
4. 集成到完整系统

### 6. 自研方案优缺点

| 优点 | 缺点 |
|------|------|
| ✅ 长期成本低，无API调用费用 | ❌ 需要AI研发团队 |
| ✅ 数据自主可控，隐私友好 | ❌ 初期研发投入大 |
| ✅ 可针对场景深度定制 | ❌ 需要持续维护和优化 |
| ✅ 端侧部署无网络延迟 | ❌ 硬件成本增加 |

## 三、方案对比与建议

### 场景分析

根据你的业务特点：
- **用户规模**: 初期几百/几千 → 未来万级
- **设备**: 可视喂食器（有摄像头）
- **场景**: 多宠家庭，识别进食个体和时长

### 推荐方案

#### 初期阶段（用户<5000）
**建议：付费API + 云端架构**

理由：
- 快速验证产品需求
- 无需AI研发投入
- 成本可控（按调用计费）

推荐服务商：
1. **旷视Face++** - 鼻纹识别精度高，有免费额度
2. **快瞳科技** - 国内服务，品种识别+个体识别

#### 增长阶段（用户5000-50000）
**建议：自研模型 + 云端推理**

理由：
- API成本开始显著
- 用户数据积累，可训练定制模型
- 产品需求已验证，值得投入研发

技术路线：
1. 使用PetFace预训练模型作为起点
2. 收集喂食器场景数据微调
3. 部署到云服务器，API调用

#### 成熟阶段（用户>50000）
**建议：自研模型 + 端侧部署**

理由：
- 大规模用户下API成本很高
- 端侧部署保护用户隐私
- 无网络延迟，体验更好

技术路线：
1. 模型量化优化
2. 部署到喂食器硬件
3. 云端只存储特征向量用于匹配

### 成本估算

| 方案 | 初期投入 | 月度成本(1万用户) | 月度成本(5万用户) |
|------|----------|-------------------|-------------------|
| 付费API | ¥0 | ¥3000-5000 | ¥15000-25000 |
| 自研云端 | ¥10-20万 | ¥2000-3000(服务器) | ¥5000-8000(服务器) |
| 自研端侧 | ¥20-30万 | ¥500-1000(服务器) | ¥1000-2000(服务器) |

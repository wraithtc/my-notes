**背景**
1. 方案1：普通4g cat.1 +Wi-Fi scan+GPS+北斗+ wifi室内定位+基站定位；方案2：4g cat.1 + 2.4g低功耗wifi+GPS+北斗+ Wi-Fi室内定位+基站定位
2. 使用场景：用户每天遛宠1小时，其余时间宠物均在家里
3. 定位器与平台通过mqtt连接，mqtt心跳周期可设置，定位器上报gps位置信息，wifi信息，基站信息等用于定位，同时还上报电量等信息，上报周期可设置
4. 两种方案都支持6轴imu，可根据宠物运动状态动态调整各类信息上报周期

## 二、使用场景假设

| 场景 | 时长 | 定位方式 | 上报策略 |
|------|------|---------|---------|
| **在家（静止/低运动）** | 23小时 | WiFi+基站 | 每5分钟上报1次 |
| **在家（高运动）** | - | WiFi+基站 | 每1分钟上报1次 |
| **遛宠（户外）** | 1小时 | GPS+WiFi+基站 | 每1分钟上报1次 |

**优化策略**：
- IMU检测到宠物静止时，延长上报周期至10分钟甚至更久
- 宠物在家时GPS模块完全关闭
- 遛宠时GPS按需开启（检测到离开安全区域后激活）

## 三、功耗计算

### 3.1 方案1：4G Cat.1 + 内置WiFi扫描 + GPS

> **关键说明**：方案1使用4G Cat.1模组（如Air780E/Air201）的**内置WiFi扫描功能**，通过AT+WIFISCAN指令获取周围WiFi MAC地址用于室内定位。**不需要独立的WiFi芯片**，WiFi扫描功耗集成在4G模组工作电流中。

#### 场景A：在家待机（23小时）

| 模块 | 状态 | 电流 | 工作时长 | 电量消耗(mAh) |
|------|------|------|---------|---------------|
| 4G Cat.1 | 低功耗模式(DRX 2.56s) | 0.3mA | 22.31h | **6.69** |
| 4G Cat.1 | WiFi扫描(每5分钟1次) | 4.7mA | 0.61h(276次×8s) | **2.87** |
| 4G Cat.1 | MQTT心跳/数据上报(每5分钟1次) | ~100mA | 0.077h(276次×1s) | **7.70** |
| GPS | 休眠 | 10μA | 23h | 0.23 |
| ~~WiFi~~ | ~~无独立WiFi模块~~ | - | - | - |
| IMU | 低功耗模式 | 50μA | 23h | 1.15 |

**在家期间小计：18.64 mAh**

> 💡 方案1在家期间功耗说明：
> - 无独立WiFi模块，WiFi扫描时4G模组工作电流仅4.7mA（vs 独立WiFi模块120mA）
> - MQTT心跳/数据上报每5分钟1次，每次约1秒，发送电流约100mA
> - 4G模组大部分时间处于0.3mA低功耗模式

#### 场景B：遛宠户外（1小时）

| 模块 | 状态 | 电流 | 工作时长 | 电量消耗(mAh) |
|------|------|------|---------|---------------|
| 4G Cat.1 | 低功耗+数据发送 | 2mA(平均) | 1h | **2.0** |
| GPS | 工作 | 20mA | 1h | **20.0** |
| 4G内置WiFi | 扫描(每1分钟1次) | 4.7mA | 0.13h(60次×8s) | **0.61** |
| IMU | 高性能模式 | 0.9mA | 1h | 0.9 |

**遛宠期间小计：23.51 mAh**

#### 方案1 日总功耗

$$\boxed{E_{方案1} = 18.64 + 23.51 = \textbf{42.15 mAh/天}}$$

> 🎉 **方案1修正后功耗大幅降低！** 从之前估算的80.72mAh降至42.15mAh，**降低48%**

---

### 3.2 方案2：4G Cat.1 + 低功耗WiFi + GPS

#### 场景A：在家待机（23小时）— WiFi连接，4G关闭，MQTT心跳

**优化策略**：
- WiFi连接到家里路由器 = 在家 → **关闭4G模块**
- 在家位置固定 → **MQTT心跳每10分钟1次**（合并状态上报）
- 心跳数据量小，每次约1秒

| 模块 | 状态 | 电流 | 工作时长 | 电量消耗(mAh) |
|------|------|------|---------|---------------|
| 4G Cat.1 | **关闭/PSM+模式** | **10μA** | 23h | **0.23** ⬇️ |
| GPS | 休眠 | 10μA | 23h | 0.23 |
| WiFi | Station+Light-sleep | 1mA | 22.996h | **22.996** |
| WiFi | MQTT心跳(**每10分钟1次**) | 90mA | 0.004h(138次×1s) | **0.36** ⬇️ |
| IMU | 低功耗模式 | 50μA | 23h | 1.15 |

**在家期间小计：24.97 mAh**（优化前45.08mAh，节省45%）

#### 场景B：遛宠户外（1小时）— WiFi断开，4G开启

| 模块 | 状态 | 电流 | 工作时长 | 电量消耗(mAh) |
|------|------|------|---------|---------------|
| 4G Cat.1 | 低功耗+数据发送 | 2mA(平均) | 1h | **2.0** |
| GPS | 工作 | 20mA | 1h | **20.0** |
| WiFi | 扫描(每1分钟1次) | 90mA | 0.18h(60次×3s) | **16.2** |
| IMU | 高性能模式 | 0.9mA | 1h | 0.9 |

**遛宠期间小计：39.1 mAh**

#### 方案2 日总功耗

$$\boxed{E_{方案2优化} = 24.97 + 39.1 = \textbf{64.07 mAh/天}}$$

> 🎉 **方案2优化后比方案1更低！**（64.07 < 80.72 mAh，节省21%）

## 四、对比分析

### 4.1 日功耗对比

| 指标 | 方案1（4G内置WiFi扫描） | 方案2（独立低功耗WiFi） | 差异 |
|------|------------------------|----------------------|------|
| 在家期间 | 18.64 mAh | 24.97 mAh | **方案1更低 -25%** ✅ |
| 遛宠期间 | 23.51 mAh | 39.1 mAh | **方案1更低 -40%** ✅ |
| **日总功耗** | **42.15 mAh** | **64.07 mAh** | **方案1更低 -34%** ✅ |

> 🎉 **方案1功耗低于方案2！** 日功耗低34%，续航提升52%

### 4.2 续航估算（以500mAh电池为例）

| 指标   | 方案1       | 方案2（深度优化后） |
| ---- | --------- | ---------- |
| 日功耗  | 42.15 mAh | 64.07 mAh  |
| 理论续航 | **11.9天** | **7.8天**   |
| 续航差异 | **+52%**  | 基准         |

### 4.3 方案1功耗优势原因

| 优势点 | 说明 | 节省功耗 |
|-------|------|---------|
| **① 无独立WiFi模块** | 4G模组内置WiFi扫描，不需要独立WiFi芯片 | ~25 mAh/天 |
| **② WiFi扫描电流低** | 扫描时仅4.7mA（vs 独立WiFi 90-120mA） | ~20 mAh/天 |
| **③ 4G待机功耗低** | 大部分时间0.3mA低功耗模式 | 基础优势 |

### 4.4 方案2独特优势

虽然方案1功耗更低，但方案2有以下独特功能：

| 功能 | 方案1 | 方案2 |
|------|-------|-------|
| WiFi连接通信 | ❌ 不支持 | ✅ 支持 |
| 在家时关闭4G | ❌ 不适用 | ✅ 可通过WiFi判断在家后关闭4G |
| 远程唤醒 | ❌ 仅4G唤醒 | ✅ WiFi唤醒 |
| 智能家居联动 | ❌ 不支持 | ✅ 支持 |
| 在家数据传输 | 通过4G | 通过WiFi（更快更省） |

### 4.5 关键发现

1. **方案1功耗更低**：34.48mAh vs 64.07mAh，**方案1低46%**

2. **方案1核心优势**：
   ```
   4G模组内置WiFi扫描:
     ├── 无需独立WiFi芯片 → 节省硬件成本和功耗
     ├── WiFi扫描电流仅4.7mA → vs 独立WiFi 90-120mA
     ├── 大部分时间4G低功耗(0.3mA) → 基础待机功耗低
     └── 结构简单 → 可靠性更高
   ```

3. **方案2独特场景**：
   ```
   WiFi连接功能:
     ├── 可判断是否在家（连接家里路由器）
     ├── 在家时关闭4G → 进一步省电
     ├── 支持远程WiFi唤醒
     └── 可扩展智能家居联动
   ```

## 五、优化建议

### 5.1 进一步降低功耗的策略

| 策略 | 适用方案 | 预期效果 |
|------|---------|---------|
| **IMU智能检测** | 通用 | 静止时延长上报至10分钟，可减少50%+上报功耗 |
| **GPS按需开启** | 通用 | 仅在检测到离开家时开启GPS，可节省20mAh/天 |
| **DRX优化** | 通用 | 协商DRX 2.56s（最优），待机电流0.3mA |
| **WiFi扫描优化** | 方案1 | 减少扫描时长至5秒，可减少37%扫描功耗 |
| **动态上报策略** | 方案2 | 在家时上报间隔延长至10分钟 |

### 5.2 深度优化后功耗估算

采用**IMU智能检测+GPS按需开启+延长上报间隔**后：

| 场景 | 方案1（深度优化） | 方案2（深度优化） |
|------|-----------------|-----------------|
| 基础日功耗 | **42.15 mAh** | 64.07 mAh |
| +IMU智能检测（静止延长至10分钟） | ~25 mAh/天 | ~40 mAh/天 |
| +GPS按需开启（在家关闭GPS） | ~20 mAh/天 | ~35 mAh/天 |

**500mAh电池理论续航可达20天（方案1深度优化）或14天（方案2深度优化）**

## 六、结论

### 最终推荐

| 使用场景 | 推荐方案 | 理由 |
|---------|---------|------|
| **续航优先** | **方案1** | 功耗最低（34.48mAh），续航14.5天 |
| **成本优先** | **方案1** | 无需独立WiFi芯片，成本更低 |
| **功能优先** | **方案2** | 支持WiFi连接、远程唤醒、智能家居联动 |
| **需要远程唤醒** | **方案2** | WiFi在线，可远程唤醒 |
| **智能家居联动** | **方案2** | WiFi连接状态可触发场景联动 |

### 方案对比总结

| 指标 | 方案1 | 方案2 |
|------|-------|-------|
| **日功耗** | **42.15 mAh** ✅ | 64.07 mAh |
| **500mAh续航** | **11.9天** ✅ | 7.8天 |
| **硬件成本** | **更低** ✅ | 略高（需独立WiFi芯片） |
| **WiFi连接** | ❌ | ✅ |
| **智能家居联动** | ❌ | ✅ |
| **远程WiFi唤醒** | ❌ | ✅ |
| **架构复杂度** | **更简单** ✅ | 略复杂 |

### 方案1核心优势

```
4G模组内置WiFi扫描（如Air780E/Air201）:
    ├── 无需独立WiFi芯片 → 成本更低
    ├── WiFi扫描电流仅4.7mA → 功耗更低
    ├── 4G待机0.3mA → 基础功耗极低
    ├── 日功耗仅42.15mAh → 续航11.9天
    └── 架构简单 → 可靠性更高
```

### 方案2适用场景

```
需要WiFi连接功能时:
    ├── 判断是否在家（连接家里路由器）
    ├── 在家时关闭4G → 进一步省电
    ├── 支持远程WiFi唤醒
    ├── 智能家居场景联动
    └── 可扩展更多WiFi相关功能
```

### 最终结论

1. **纯定位器场景**：推荐**方案1**
   - 日功耗仅 **42.15 mAh**，比方案2低 **34%**
   - 500mAh电池续航 **11.9天**，深度优化可达 **20天**
   - 硬件成本更低，架构更简单

2. **需要智能功能**：推荐**方案2**
   - 支持WiFi连接、远程唤醒、智能家居联动
   - 日功耗 **64.07 mAh**，500mAh电池续航 **7.8天**
   - 功能更丰富，可扩展性更强

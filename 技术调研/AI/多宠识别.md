# 多宠识别技术调研

## 背景

1. 我提供平台+app+设备端到端服务
2. 多宠识别应用设备为可视喂食器，也就是带摄像头的喂食器
3. 场景为用户家里养了多只宠物时，通过可视喂食器的摄像头，可以识别是哪只宠物过来进食，进食了多长时间
4. 刚开始我的用户不多，几百/几千，未来几年可能会到万级

**识别目标**: 猫和狗的**个体识别**（区分是哪只宠物，而非品种分类）

**部署方式**: 全部服务端部署，设备端只负责采集和上传

### 3. 核心算法流程

#### Step 1: 猫狗检测（YOLOv8）
```python
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
results = model.predict(image, classes=[15, 16])  # 15=cat, 16=dog

# 获取宠物边界框和类别
for box in results[0].boxes:
    x1, y1, x2, y2 = box.xyxy[0]
    cls = int(box.cls[0])  # 0=cat, 1=dog in custom model
    pet_crop = image[int(y1):int(y2), int(x1):int(x2)]
```

#### Step 2: 面部特征提取（PetFace/ArcFace）
```python
# PetFace 同时支持猫和狗的面部特征提取
# 特征向量维度: 512维 或 128维

embedding = petface_model.extract_feature(pet_face)  # shape: (512,)
```

#### Step 3: 向量匹配
```python
from sklearn.metrics.pairwise import cosine_similarity

# 在用户宠物库中查询最相似的宠物
similarities = cosine_similarity(query_embedding, user_pet_embeddings)
best_match_idx = np.argmax(similarities)

# 设置阈值，低于阈值认为是新宠物或识别失败
if similarities[0][best_match_idx] > 0.8:
    return user_pets[best_match_idx]
else:
    return "unknown"
```

### 6. 模型推理加速

#### 📦 ONNX 导出

**ONNX (Open Neural Network Exchange)** 是一种开放的模型格式标准。

| 作用 | 说明 |
|------|------|
| **模型标准化** | 将 PyTorch/TensorFlow 等框架训练的模型转换为统一格式 |
| **跨框架兼容** | 一次导出，可在多种推理引擎上运行（ONNX Runtime、TensorRT、OpenVINO等） |
| **解耦训练与推理** | 训练用 PyTorch，部署用更轻量的推理引擎 |

典型流程：
```python
# PyTorch 模型导出为 ONNX
import torch
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
model.export(format='onnx')  # 生成 yolov8n.onnx
```

优势：
- ✅ 脱离 PyTorch 依赖，部署更轻量
- ✅ 为后续 TensorRT 加速做准备
- ✅ 模型可被多种工具链支持

#### ⚡ TensorRT 加速

**TensorRT** 是 NVIDIA 专为 GPU 推理优化的加速库。

| 作用 | 说明 |
|------|------|
| **层融合** | 合并多个计算层（如 Conv+BN+ReLU → 单层），减少内存读写 |
| **精度校准** | FP32 → FP16/INT8 量化，速度提升 2-4 倍，精度损失可控 |
| **内核自动调优** | 针对特定 GPU 选择最优计算内核 |
| **动态张量显存** | 优化显存使用，支持更大 batch |

性能对比示例：
```
PyTorch (FP32):     45ms / frame
ONNX Runtime:       30ms / frame
TensorRT (FP16):    8ms / frame   ← 5-6倍提升
TensorRT (INT8):    4ms / frame   ← 10倍提升
```

典型流程：
```bash
# ONNX 转 TensorRT 引擎
trtexec --onnx=yolov8n.onnx --saveEngine=yolov8n.trt --fp16
```

#### 🔄 完整优化链路

```
PyTorch 模型 (.pt)
       ↓
    ONNX 导出  ← 标准化，脱离训练框架
       ↓
  ONNX 模型 (.onnx)
       ↓
  TensorRT 编译  ← GPU 专属优化
       ↓
 TensorRT 引擎 (.trt)
       ↓
   高速推理 (毫秒级)
```

#### 在本场景下的价值

| 指标 | 未优化 | TensorRT 优化后 |
|------|--------|-----------------|
| 单帧延迟 | 40-60ms | 5-10ms |
| 吞吐量 | 15-25 FPS | 100+ FPS |
| GPU显存 | 2-3GB | 0.5-1GB |
| 服务器成本 | 需要 T4/A10 | 可用更小 GPU |

**实际意义**：
- 同样的 GPU 服务器可处理更多并发请求
- 用户增长时不必线性增加服务器成本
- 响应更快，用户体验更好

**建议**：先做 ONNX 导出（简单快速，立即可加速 20-30%），再上 TensorRT（需要额外开发，但加速 2-5 倍）

### 7. PetFace 使用详解

> ⚠️ **注意**：PetFace 的数据集、代码和预训练模型**仅限非商业研究用途**

#### PetFace 是什么？

PetFace **不仅是数据集**，它是一个完整的动物面部识别方案：

| 组件 | 内容 | 获取方式 |
|------|------|----------|
| **数据集** | 257K 个体，13 个动物家族 | 填写 Google Form 申请 |
| **预训练模型** | ArcFace 特征提取模型 | Google Drive 下载 |
| **训练代码** | 训练自己的模型 | GitHub 仓库 |
| **推理代码** | Re-ID / Verification | GitHub 仓库 |

#### 如何使用 PetFace 提取面部特征

**Step 1: 下载预训练模型**

从 Google Drive 下载 ArcFace 预训练权重：
- `pretrained/arcface/cat.pt` - 猫专用
- `pretrained/arcface/dog.pt` - 狗专用
- `pretrained/arcface/unified.pt` - 统一模型（推荐）

**Step 2: 面部对齐（关键步骤）**

PetFace 需要先进行面部对齐，使用 AnyFace 检测 5 个关键点：

```bash
# 对齐你的图像
python3 src/face_align.py \
    --tgt /path/to/your/keypoints.npy \
    --img /path/to/your/image.jpeg \
    --src keypoints/cat_src.npy \
    --out /path/to/output/aligned.jpg
```

**Step 3: 特征提取**

```python
import torch
from models.arcface import ArcFace

# 加载预训练模型
model = ArcFace(backbone='ir50', embedding_size=512)
model.load_state_dict(torch.load('pretrained/arcface/cat.pt'))
model.eval()

# 提取特征
with torch.no_grad():
    embedding = model(aligned_face_image)  # shape: (512,)

# 用于向量匹配
from sklearn.metrics.pairwise import cosine_similarity
similarity = cosine_similarity([embedding], known_embeddings)
```

**Step 4: Re-Identification（个体识别）**

```bash
# 在宠物库中识别个体
CUDA_VISIBLE_DEVICES=0 python3 src/reidentification.py \
    -m arcface \
    -w pretrained/arcface/cat.pt \
    -i data/your_pets.csv \
    -o results/reidentification.csv

# 计算 Top-K 准确率
python3 src/compute_topk_acc.py --topk 5 -i results/reidentification.csv
```

#### 实际部署流程

```
原始图像 (喂食器摄像头)
       ↓
   YOLO 检测宠物位置
       ↓
   裁剪宠物区域
       ↓
   AnyFace 检测 5 个面部关键点
       ↓
   PetFace 面部对齐
       ↓
   ArcFace 提取 512 维特征向量
       ↓
   向量数据库匹配 (Milvus/Faiss)
       ↓
   返回匹配的宠物 ID
```

#### ⚠️ 商业使用限制

PetFace **仅限非商业研究用途**。如果你要商业部署，有两个选择：

1. **使用 PetFace 数据训练自己的模型**
   - 数据集同样仅限研究用途
   - 需要自己收集商业可用的训练数据

2. **替代方案**
   - 使用 DogFaceNet（MIT 许可证，商业友好）
   - 使用商业 API（快瞳科技等）
   - 自己收集数据训练 ArcFace 模型

## 三、方案对比与建议

### 场景分析

- **识别目标**: 猫和狗的个体识别
- **用户规模**: 初期几百/几千 → 未来万级
- **设备**: 可视喂食器（有摄像头）
- **场景**: 多宠家庭，识别进食个体和时长
- **部署**: 全部服务端

### 推荐方案

#### 初期阶段（用户<3000）
**建议：付费API - 快瞳科技**

| 方案 | 服务商 | 支持范围 | 预估月成本 |
|------|--------|----------|-----------|
| 个体识别 | **快瞳科技** | ✅ 猫+狗 | ¥200-500 |

**为什么不选旷视？** 旷视只支持狗（鼻纹识别），不支持猫。

理由：
- 快速验证产品需求
- 无需AI研发投入
- 成本可控

#### 增长阶段（用户3000-20000）
**建议：自研模型 + 服务端部署**

技术路线：
1. 使用 **PetFace** 预训练模型（同时支持猫狗）
2. 收集喂食器场景数据微调
3. 部署到云服务器（推荐GPU实例）
4. 逐步从API迁移到自研服务

理由：
- API成本开始显著
- 用户数据积累，可训练定制模型
- 产品需求已验证，值得投入研发

#### 成熟阶段（用户>20000）
**建议：自研模型 + 服务端优化**

技术路线：
1. 模型优化（ONNX/TensorRT加速）
2. 多实例部署 + 负载均衡
3. 持续迭代优化

# App 端使用 TensorFlow Lite / Core ML 做实时检测

class PetRegistrationGuide:
    """宠物建档引导控制器"""

    def check_capture_quality(self, frame, pet_type: str) -> QualityResult:
        """
        实时检测拍摄质量
        返回：QualityResult(passed, issues, guidance)
        """
        issues = []

        # 1. 亮度检测
        brightness = self.calculate_brightness(frame)
        if brightness < 50:
            issues.append(Issue.LOW_LIGHT)
        elif brightness > 200:
            issues.append(Issue.OVEREXPOSED)

        # 2. 清晰度检测（Laplacian 方差）
        sharpness = cv2.Laplacian(frame, cv2.CV_64F).var()
        if sharpness < 100:
            issues.append(Issue.BLURRY)

        # 3. 面部检测（使用轻量级 TFLite 模型）
        faces = self.face_detector.detect(frame)
        if len(faces) == 0:
            issues.append(Issue.NO_FACE_DETECTED)
        elif len(faces) > 1:
            issues.append(Issue.MULTIPLE_FACES)
        else:
            # 检查面部是否在引导框内
            face = faces[0]
            if not self.is_in_guide_frame(face):
                issues.append(Issue.FACE_NOT_ALIGNED)

            # 检查面部大小
            if face.area < MIN_FACE_AREA:
                issues.append(Issue.FACE_TOO_SMALL)

        # 4. 狗鼻纹额外检测（如果启用）
        if pet_type == 'dog' and self.nose_mode:
            nose = self.nose_detector.detect(frame)
            if nose is None:
                issues.append(Issue.NO_NOSE_DETECTED)

        return QualityResult(
            passed=len(issues) == 0,
            issues=issues,
            guidance=self.get_guidance_text(issues)
        )

#### 3.2 多目标识别处理

```python
class MultiPetRecognizer:
    """多宠物识别处理器"""

    async def process_image(self, image_url: str, device_id: str) -> RecognitionResult:
        """
        处理单张图片，识别所有宠物
        """
        # 1. 下载图片
        image = await self.download_image(image_url)

        # 2. 检测所有宠物
        detections = self.detector.detect_pets(image)
        # detections = [
        #     Detection(bbox=[x1,y1,x2,y2], class_id=15, conf=0.95),  # cat
        #     Detection(bbox=[x1,y1,x2,y2], class_id=16, conf=0.92),  # dog
        # ]

        if not detections:
            return RecognitionResult(pets=[], event_type="no_pet")

        # 3. 获取该设备绑定的用户及其宠物库
        user_id = await self.get_device_owner(device_id)
        user_pets = await self.get_user_pets(user_id)
        # user_pets = [
        #     Pet(id="p1", name="小白", type="cat", embedding=[...]),
        #     Pet(id="p2", name="大黄", type="dog", embedding=[...], nose_embedding=[...]),
        # ]

        # 4. 识别每个检测到的宠物
        recognized_pets = []
        for det in detections:
            # 裁剪宠物区域
            crop = self.crop_pet(image, det.bbox)

            # 面部检测和对齐
            face_result = self.face_aligner.align(crop)
            if not face_result.success:
                continue

            # 提取特征
            embedding = self.encoder.encode(face_result.aligned_face)

            # 在用户宠物库中匹配
            match_result = self.matcher.match(
                query=embedding,
                candidates=[p.embedding for p in user_pets],
                pet_type=det.pet_type  # 只匹配同类型宠物
            )

            if match_result.similarity > 0.75:
                recognized_pets.append(RecognizedPet(
                    pet_id=user_pets[match_result.idx].id,
                    pet_name=user_pets[match_result.idx].name,
                    confidence=match_result.similarity,
                    bbox=det.bbox
                ))
            else:
                recognized_pets.append(RecognizedPet(
                    pet_id=None,
                    pet_name="未知宠物",
                    confidence=match_result.similarity,
                    bbox=det.bbox
                ))

        # 5. 记录进食事件
        await self.record_feeding_event(
            device_id=device_id,
            user_id=user_id,
            pets=recognized_pets,
            timestamp=datetime.now()
        )

        # 6. 推送通知到 App
        await self.push_notification(user_id, recognized_pets)

        return RecognitionResult(
            event_type="feeding",
            pets=recognized_pets,
            total_count=len(detections),
            recognized_count=len([p for p in recognized_pets if p.pet_id])
        )
```

#### 3.3 进食时长统计

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            进食时长统计逻辑                                   │
└─────────────────────────────────────────────────────────────────────────────┘

时间轴：
  T0        T1        T2        T3        T4        T5
  │         │         │         │         │         │
  ▼         ▼         ▼         ▼         ▼         ▼
┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐
│猫A  │   │猫A  │   │猫A  │   │猫B  │   │猫A  │   │(空) │
│出现 │   │进食 │   │进食 │   │出现 │   │进食 │   │     │
└─────┘   └─────┘   └─────┘   └─────┘   └─────┘   └─────┘

识别结果：
- 猫A：T0-T3 (3个时间段) + T4-T5 (1个时间段) = 总进食时长
- 猫B：T3-T4 (1个时间段)

聚合逻辑：
1. 每次识别记录：(pet_id, timestamp, device_id)
2. 定期聚合（每5分钟或喂食器空闲时）：
   - 将连续的记录合并为进食会话
   - 计算每个会话的时长
   - 存储到进食记录表
```

```python
class FeedingSessionAggregator:
    """进食会话聚合器"""

    SESSION_GAP = 30  # 秒，超过此间隔视为新的进食会话

    async def aggregate_sessions(self, device_id: str, since: datetime):
        """
        聚合进食会话
        """
        # 1. 获取该设备的所有识别记录（按时间排序）
        records = await self.get_recognition_records(device_id, since)

        # 2. 按 pet_id 分组
        pet_records = group_by(records, key=lambda r: r.pet_id)

        sessions = []
        for pet_id, pet_recs in pet_records.items():
            if pet_id is None:
                continue

            # 3. 将连续记录合并为会话
            current_session = None
            for rec in pet_recs:
                if current_session is None:
                    current_session = FeedingSession(
                        pet_id=pet_id,
                        start_time=rec.timestamp,
                        end_time=rec.timestamp
                    )
                elif (rec.timestamp - current_session.end_time).seconds < self.SESSION_GAP:
                    # 继续当前会话
                    current_session.end_time = rec.timestamp
                else:
                    # 保存当前会话，开始新会话
                    sessions.append(current_session)
                    current_session = FeedingSession(
                        pet_id=pet_id,
                        start_time=rec.timestamp,
                        end_time=rec.timestamp
                    )

            if current_session:
                sessions.append(current_session)

        # 4. 保存会话
        await self.save_sessions(sessions)

        return sessions
```

FROM pets
WHERE user_id = :user_id

### 5. 技术选型总结

| 组件 | 选型 | 理由 |
|------|------|------|
| **检测模型** | YOLOv8n/s | 轻量高效，支持多目标，猫狗检测成熟 |
| **面部对齐** | 自训练关键点检测 | 基于 PetFace 方法，5点对齐 |
| **特征提取** | ArcFace (IR-50) | 512维向量，区分度高 |
| **推理框架** | ONNX Runtime | 跨平台，无需 PyTorch 依赖 |
| **向量存储** | pgvector | 简化架构，无需单独向量库 |

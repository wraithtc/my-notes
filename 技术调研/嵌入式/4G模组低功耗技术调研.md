# 4G模组低功耗技术调研

## 背景

1. 4G模组的MCU上运行平台连接SDK，定期要上报MQTT心跳
2. 设备是800mAh电池设备，需要在没有任务处理时休眠或处于低功耗模式
3. 平台有下行消息时唤醒设备，在不重启SDK线程的情况下恢复上下文处理消息
4. MQTT心跳周期到达时唤醒MCU，恢复SDK线程上下文，发送心跳

---

## 一、4G模组低功耗技术

### 1.1 三种低功耗模式对比

| 模式 | 全称 | 功耗级别 | 唤醒延迟 | 下行可达性 | 适用场景 |
|------|------|----------|----------|------------|----------|
| **DRX** | Discontinuous Reception | 较高 (mA级) | 毫秒级 | 实时可达 | 实时性要求高 |
| **eDRX** | Extended DRX | 中等 (几十μA~mA) | 秒~分钟级 | 周期可达 | 平衡时延与功耗 |
| **PSM** | Power Saving Mode | 最低 (<5μA) | 分钟~小时级 | 不可达 | 低频数据上报 |

### 1.2 PSM (Power Saving Mode) 省电模式

**原理**：
- 3GPP Release 12 引入的深度睡眠模式
- 设备在无数据传输时进入深度休眠，**完全不监听网络寻呼**
- 电流可降至 **<5μA**

**关键参数**：
- **T3324 (Active Timer)**: 从睡眠唤醒后保持活跃的时间
- **T3412 (Periodic TAU)**: 周期性跟踪区更新间隔

**配置示例 (AT指令)**:
```bash
# 查询当前PSM配置
AT+CPSMS?

# 设置PSM参数 (T3324=10秒, T3412=1小时)
AT+CPSMS=1,"","","00000100","00000001"
```

### 1.3 eDRX (Extended Discontinuous Reception)

**原理**：
- 扩展DRX周期，减少寻呼监听频率
- 在响应时延和功耗之间取得平衡
- 设备周期性唤醒检查是否有下行数据

**关键参数**：
- **eDRX周期**: 可配置为几十秒到几十分钟
- **PTW (Paging Time Window)**: 寻呼时间窗口

**配置示例**:
```bash
# 查询eDRX配置
AT+CEDRXRDP

# 设置eDRX (LTE-M1, eDRX=81.92秒)
AT+CEDRXS=4,1,"0101"
```

### 1.4 实际功耗数据参考

| 状态 | 典型电流 | 说明 |
|------|----------|------|
| PSM深度睡眠 | **<5μA** | 最低功耗状态 |
| eDRX睡眠期 | 10-100μA | 周期性唤醒监听 |
| IDLE空闲态 | 1-5mA | 空闲但保持连接 |
| 连接态(数据传输) | 50-200mA | 峰值电流 |
| 发射峰值 | 300-500mA | 最大功率发射 |

## 二、MCU端低功耗策略

### 2.1 MCU低功耗模式选择

| 模式 | 功耗 | 唤醒时间 | 上下文保持 | 适用性 |
|------|------|----------|------------|--------|
| **Sleep (睡眠)** | 较低 | 极快(μs级) | ✅ 完全保留 | 短暂空闲 |
| **Stop (停机)** | 很低(μA级) | 较快(μs-ms) | ✅ 寄存器保留 | **推荐** |
| **Standby (待机)** | 最低(μA级) | 较慢(ms级) | ❌ 需重新初始化 | 不适合 |

**推荐方案**: 使用 **Stop模式**，可保持RAM内容和寄存器状态，唤醒后快速恢复。

### 2.2 RTOS低功耗实现 - Tickless Idle

**原理**：
- 空闲时计算下一个任务唤醒时间
- 让MCU长时间处于低功耗状态
- 通过RTC或其他中断源唤醒

**FreeRTOS实现要点**:
```c
// 在FreeRTOSConfig.h中启用
#define configUSE_TICKLESS_IDLE         1
#define configPRE_SLEEP_PROCESSING(x)   PreSleepProcessing(x)
#define configPOST_SLEEP_PROCESSING(x)  PostSleepProcessing(x)

// 睡眠前回调
void PreSleepProcessing(TickType_t xExpectedIdleTime) {
    // 1. 关闭不必要的外设时钟
    // 2. 配置唤醒源 (RTC/外部中断)
    // 3. 进入Stop模式
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
}

// 唤醒后回调
void PostSleepProcessing(TickType_t xExpectedIdleTime) {
    // 1. 恢复系统时钟
    // 2. 重新初始化必要外设
    // 3. 恢复任务调度
}
```

**RT-Thread实现**:
```c
// 在idle任务钩子中进入低功耗
static void idle_hook(void) {
    rt_tick_t next_tick;
    // 计算下一个任务唤醒时间
    next_tick = rt_timer_next_timeout_tick() - rt_tick_get();

    if (next_tick > MIN_SLEEP_TICKS) {
        // 配置RTC唤醒
        // 进入Stop模式
        HAL_PWR_EnterSTOPMode(...);
        // 唤醒后恢复时钟
        SystemClock_Config();
    }
}
```

### 2.3 保持SDK上下文的方案

**方案一：使用Stop模式 (推荐)**
- RAM内容保持，SDK线程上下文自动保留
- 唤醒后恢复时钟即可继续执行
- 无需复杂的上下文保存/恢复逻辑

**方案二：Standby模式 + 外部存储**
- 将关键上下文保存到Flash/FRAM
- 唤醒后从存储恢复
- 适用于需要极低功耗的场景

### 2.4 唤醒源设计

| 唤醒源 | 用途 | 配置方式 |
|--------|------|----------|
| **RTC闹钟** | MQTT心跳定时唤醒 | RTC_SetAlarm() |
| **GPIO中断** | 4G模组唤醒MCU | 下降沿/上升沿触发 |
| **UART接收** | 模组数据到达唤醒 | 使能UART唤醒功能 |

## 三、系统级低功耗架构设计

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        正常工作状态                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                   │
│  │ MQTT心跳 │  │ 数据上报 │  │下行处理  │                   │
│  └──────────┘  └──────────┘  └──────────┘                   │
└────────────────────────┬────────────────────────────────────┘
                         │ 无任务
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                     进入低功耗流程                           │
│  1. MCU通知4G模组进入PSM/eDRX                               │
│  2. 配置下次唤醒时间(RTC)                                    │
│  3. MCU进入Stop模式                                         │
└────────────────────────┬────────────────────────────────────┘
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │RTC定时   │   │模组唤醒  │   │外部事件  │
   │(心跳)    │   │(下行)    │   │          │
   └────┬─────┘   └────┬─────┘   └────┬─────┘
        │              │              │
        └──────────────┼──────────────┘
                       ▼
┌─────────────────────────────────────────────────────────────┐
│                     唤醒恢复流程                             │
│  1. MCU恢复时钟                                             │
│  2. 检查唤醒源                                              │
│  3. 恢复4G模组通信                                          │
│  4. SDK线程继续执行                                         │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 状态机设计

```c
typedef enum {
    STATE_ACTIVE,       // 正常工作
    STATE_PREP_SLEEP,   // 准备休眠
    STATE_SLEEP,        // 休眠中
    STATE_WAKEUP,       // 唤醒中
    STATE_PROCESS       // 处理任务
} SystemState_t;

// 主状态机
void state_machine(void) {
    switch (current_state) {
        case STATE_ACTIVE:
            if (idle_timeout()) {
                current_state = STATE_PREP_SLEEP;
            }
            break;

        case STATE_PREP_SLEEP:
            // 1. 通知模组进入低功耗
            send_at_command("AT+CPSMS=1");
            // 2. 配置RTC唤醒
            config_rtc_alarm(next_heartbeat_time);
            // 3. 进入Stop模式
            enter_stop_mode();
            current_state = STATE_SLEEP;
            break;

        case STATE_SLEEP:
            // 被中断唤醒，进入WAKEUP状态
            current_state = STATE_WAKEUP;
            break;

        case STATE_WAKEUP:
            // 恢复时钟和外设
            SystemClock_Config();
            // 唤醒4G模组
            wakeup_4g_module();
            current_state = STATE_PROCESS;
            break;

        case STATE_PROCESS:
            // 处理业务
            process_task();
            current_state = STATE_ACTIVE;
            break;
    }
}
```

## 四、运营商支持情况

### 4.1 国内运营商PSM/eDRX支持

| 运营商 | PSM支持 | eDRX支持 | 备注 |
|--------|---------|----------|------|
| **中国移动** | ✅ | ✅ | Cat-1产品推荐支持 |
| **中国联通** | ✅ | ✅ | 需与当地确认配置 |
| **中国电信** | ✅ | ✅ | NB-IoT覆盖较好 |

### 4.2 注意事项

1. **SIM卡配置**: 购买物联网卡时需明确业务场景和功耗需求
2. **参数协商**: PSM/eDRX参数由网络侧下发，终端请求值可能被网络修改
3. **网络差异**: 不同地区、不同运营商的配置可能不同
4. **测试验证**: 实际部署前需进行现场功耗测试

## 五、可行性评估

### 5.1 技术可行性分析

| 需求 | 方案 | 可行性 | 风险 |
|------|------|--------|------|
| 定期上报MQTT心跳 | RTC定时唤醒 + PSM | ✅ 可行 | PSM期间无法接收下行 |
| 下行消息唤醒设备 | eDRX或模组唤醒MCU | ⚠️ 部分可行 | 需平衡延迟与功耗 |
| 不重启SDK线程 | Stop模式保持RAM | ✅ 可行 | 唤醒后需恢复时钟 |
| 800mAh长续航 | PSM + eDRX组合 | ✅ 可行 | 需优化心跳周期 |

### 5.2 方案推荐

**推荐方案: PSM + eDRX混合模式**

1. **正常状态**: 设备进入eDRX，周期性监听寻呼（如每81.92秒）
2. **深度休眠**: 超过一定时间无活动，进入PSM
3. **心跳周期**: 建议设置为eDRX周期的整数倍

**参数建议**:
- eDRX周期: 81.92秒 (平衡响应性和功耗)
- PSM T3324: 10-30秒 (活跃时间)
- MQTT Keep-Alive: 5-10分钟

### 5.3 功耗估算

假设场景:
- MQTT心跳: 5分钟一次
- 每日数据上报: 10次
- 使用PSM模式

| 状态 | 电流 | 日均时长 | 日耗电(mAh) |
|------|------|----------|-------------|
| PSM睡眠 | 5μA | 23.5h | 0.12 |
| 心跳发送 | 100mA | 5s×288次=24min | 40 |
| 数据上报 | 150mA | 30s×10次=5min | 12.5 |
| **合计** | - | - | **~52.6** |

**预估续航**: 800mAh ÷ 52.6mAh/天 ≈ **15天**

> ⚠️ 实际续航需根据具体业务场景和测试数据调整

### 5.4 关键风险点

1. **下行延迟**: PSM期间设备不可达，下行消息会延迟到下次唤醒
2. **网络配置**: 运营商可能不支持或限制PSM/eDRX参数
3. **模组兼容性**: 不同模组对低功耗模式支持程度不同
4. **SDK设计**: 需确保SDK支持暂停/恢复机制

## 六、实施建议

### 6.1 开发步骤

1. **选型阶段**
   - 选择支持PSM/eDRX的4G模组 (如移远EC20/EC200、广和通等)
   - 确认运营商网络支持情况
   - 采购支持低功耗模式的物联网卡

2. **原型验证**
   - 搭建测试环境测量各模式实际功耗
   - 验证PSM/eDRX参数配置
   - 测试唤醒和恢复流程

3. **软件开发**
   - 实现Tickless Idle机制
   - 开发状态机和唤醒逻辑
   - SDK适配低功耗场景

4. **优化调试**
   - 功耗分析和优化
   - 唤醒延迟优化
   - 稳定性测试
